# IDEEZA Creator — Project Guide

`ideeza-creator-panel` — a browser-based **AI-driven hardware-creation
platform**. A maker describes an electronics idea; AI drafts the **schematic,
parts list and build steps**, which the maker refines in a suite of editor
modules (PCB, Code, 3D, Wiring, Preview, Brief), then **mints the design
on-chain (Utility NFT)** and shares/sells it via the community feed and
marketplace. The deepest module is an **EasyEDA-inspired schematic + PCB
editor** with a native (KiCad-less) Schematic→PCB pipeline. This is a **real
product, not a prototype** — every control must do real, verified work.

> **Next.js is modified here.** See `@AGENTS.md`: this is Next 16.x with breaking
> changes. Read `node_modules/next/dist/docs/` before writing any Next-specific
> code.

### State / store (`store.tsx`)

- One `PcbState` object; actions built with `useMemo`.
- **`merge(patch)`** — plain state update (view/UI, no undo).
  **`mergeWithHistory(patch)`** — model changes; snapshots `SNAP_KEYS` for undo/redo (diffed, so no-ops don't pollute history).
- **`stateRef.current`** — read latest state inside async/event actions.
- **`setToolAs(tool, text)`** — arms a place tool whose object carries a given name (`state.placeText`, consumed + cleared by `placeObject`). Lets several menu rows share one symbol kind honestly: Insert ▸ Power & Ground places `vcc5v` as **VCC / +5V / -5V**, and the supply glyph draws `obj.text`.
- Actions may call `actions.<other>()` (safe — invoked on events, not during render).
- **Persistence:** the *document* (`objects, pcbBoard, twoD, threeD, gridSize, gridType, unit, snapEnabled, designRules, pcbDrcConfig, pcbLayers, pcbNets, pcbDefaults, boardSettings`) auto-saves (debounced) to `localStorage` under `ideeza:pcb:doc:<projectId>`, scoped by `ideeza:manual:active`. So layer colours/visibility/lock, net colours, place defaults, grid style and DRC rule-tuning now survive reload. UI flags (zoom, panels, menus, sheets) are session-only. `saveDoc()` force-writes; `sanitizePcbDoc()` shape-checks every key on load.

### `CanvasObject` — the universal placed-object model

`kind, x, y, endX/endY` (wires), `text, rotation, color, layer, net, footprint,
comment, side, props` (typed-field bag), `scope` (`"schematic"|"pcb"`),
`sheetId` (multi-sheet), `sourceId` (cross-probe link), `points` (real polygon
rings for Combine results). Add a field here + handle it in `placed-objects.tsx`
+ (if persisted) the doc sanitizer.

### PCB module — schematic editor
- **One canvas state vocabulary, from tokens** (`tokens.css` "Canvas interaction states" → `placed-objects.tsx`): **hover** = 1px solid `--color-canvas-hover` + `--color-canvas-hover-fill` ("this is what your click would take"), suppressed while a place/draft tool is armed because the click then belongs to the tool; **selected** = 1px dashed `--color-canvas-select` + `--color-canvas-select-fill`; **net highlight** = amber (`--color-canvas-highlight`), a different hue on purpose since it marks a net, not a pick; rubber band + lasso share `--color-canvas-marquee-fill`. A wire can't carry an outline, so it speaks the same colours instead (stroke swaps, 1.7 → 2.6px, plus a glow of the select token). Every state colour used to be a hardcoded `rgba(124,45,185,…)` per call-site, so it couldn't differ per theme and drifted between kinds. **Wires are pickable, not a pixel hunt** — the visible ink stays 1.7px (`pointer-events: none`) over a transparent 9px hit band that carries the id, hover and click. Object tooltips read `R1 · resistorBox` (name + kind). The states are captured from the running editor in both themes in the canvas-states sheet artifact.
- **An armed tool says so in three places** (`tool-labels.ts` + `canvas-area.tsx`): the palette button lights up, the **hint chip** over the canvas names the tool and the next click (`GND · Click on the sheet to place · Esc cancels`; draft tools read `Click to start, click again to finish`), and one-click placers show a **ghost of the symbol** at the position it will actually land on — snapping included — drawn from `glyphFor()`, the same geometry the placed object uses, so the preview can't drift. Names come from the palette's own option labels (`buildToolLabels`), with a prettifier for menu-only tools, and a rail variant says what it will stamp (`DGND (GND)`); the status bar shows that label instead of the raw id it used to print (`vcc5v`, `netBusLabel`). The ghost, like the crosshair, is moved by direct DOM writes inside `requestAnimationFrame`.
- **Sheet templates are real** (`schem-properties.tsx`) — the Template dropdown is *derived* from (paper size + orientation): picking `A3 Portrait` sets both and the sheet redraws, changing either directly reads back as `Custom`. It used to write `schemBasic.template`, which nothing read. **The on-canvas title block is labelled** (UIUX-68) — it printed an unlabelled strip (`Ayaan K. · Rev C 1/2 SB-001 A4 Landscape 2026-07-16`), so a reader had to know the schema to tell a doc number from a date. Now the sheet title is the heading and everything else is a **label / value grid** (Company · Project · Author · Doc No. · Revision · Sheet · Date · Size), each row appearing only when that field is set. **Project falls back to the project actually open** (`state.activeProjectId` + `recentProjects`), so the row names it instead of vanishing when nobody typed one, and the header is always the IDEEZA mark — it used to print the company *or* "IDEEZA" as a fallback, so an unset company read as our branding. `Sheet ▸ Name` now renames the **active sheet** (the name the Sheets tree and page tabs show) instead of a dead field, and the title block gained the two fields the brief named: **Project** (in the subtitle line) and **Sheet size** (read-only — it *is* the border's paper size, so there is only one place to set it).
- **The canvas is designed for both themes, not inherited** — sheet grid (`--color-canvas-grid`, 12% ink: 7% vanished on white), title-block fill (`--color-canvas-card`) and its **boundary** (`--color-canvas-card-border`, 50% ink → **3.53:1** on the white sheet, **5.13:1** on the dark one; two adjacent surfaces can only carry ~1.1:1 of fill contrast, so WCAG 1.4.11's 3:1 has to come from the edge). The sheet border's stored colour is now empty-means-theme-ink instead of the `#1E1E1E` sentinel, so a user who picks near-black gets near-black.
- **Crosshair guides (schematic)** — two hairlines (`--color-canvas-crosshair`, a neutral 26% ink so it never reads as selection) follow the pointer across the whole sheet, so a pin far left is visibly in line with one far right. They live in `Crosshair` (`canvas-area.tsx`) and are updated by writing `transform` straight to the two lines behind `requestAnimationFrame` — a React state update per mouse move would re-render the canvas at pointer rate. Hidden when the pointer leaves the canvas; absent in board modes, which have rulers for the same job.
- **Cross Probe works both ways and shows where it landed** — a schematic symbol finds the footprint Convert linked to it (`footprint.sourceId === symbol.id`), and a footprint walks its own `sourceId` back to the symbol; the PCB context menu gained the row it never had. On arrival the target is selected, framed, **and pulsed** (`state.probe = {id, nonce}` → the `.ix-probe` ring, two 950 ms rings, static under `prefers-reduced-motion`), then the pulse clears itself — selection alone never answered "which one?" on a dense board.
- **Rulers are board-only** — the schematic sheet prints its own zone reference (A–D / 1–4) on the frame and the status bar shows live X/Y, so the px rulers were noise there; hiding them also returns the 22px/30px gutters to the sheet (`showRulers` in `canvas-area.tsx`).
- Canvas pan/zoom/grid; selection = **mousedown is the sole authority** (click, shift/⌘-click multi-select, drag rubber-band). Delete/Esc/Ctrl+C/X/V/A/Z/Y, Hand tool (H / hold Space).
- **Left tool palette** (split-button flyouts): Wire (Wire/Bus — the bus row draws the bus trunk, not a second wire · UIUX-48) · **Power** (VCC/+5V/−5V/GND/**DGND**/Analog GND/Power GND — each places its own symbol, matching Insert ▸ Power & Ground; sits right under Wire) · **Shapes** (Rectangle/Line/Polyline/Circle/Ellipse/Arc/Bezier) · **Net Label** (Local label · **Net Flag** — the flag had no canvas home at all · UIUX-8) · No Connect · Junction · Text (Text/Note). Every option arms a real place/draft tool. **Lasso** = real freeform-polygon selection (ray-cast point-in-polygon, `state.lasso` + start/update/commit/cancel), **Area select** = real marquee (always rubber-bands on drag). **DGND** rides the GND symbol under its own name (`setToolAs("gnd","DGND")`) — the netlist names a net from the stamped text, so it really is a separate DGND net (verified in the Nets tab beside GND), the same trick VCC/+5V/−5V use on `vcc5v`. The four other label kinds (global · hierarchical · attached · Port · Off-sheet link) live in **Insert ▸ Net Label** so one canvas button doesn't hide five, and every kind stays placeable + ⌘K-searchable. *(Removed: Bus-entry, Text ▸ Field and the Eraser row — a bus is a bundle, not a conductor, so bus-entry drew nothing electrical, and Delete/Backspace · Edit ▸ Delete · right-click ▸ Delete already own deletion.)*
- **The variant list opens like a toolbar, not a pixel hunt** — a **right-click anywhere on a tool** opens its list (and never falls through to the canvas context menu), and the left-click zone that opens it is the tool's **whole bottom strip** (38×14) instead of the old 14×14 corner square; the corner triangle stays as the recognised "has variants" cue and `.ix-tool:hover` tints just that strip, so the split is visible. Escape or an outside click closes. The list itself is **portalled to `<body>` with `position: fixed` and clamped into the viewport** (flips left at the right edge, lifts at the bottom) — it used to be absolutely positioned inside the canvas frame, which sets `overflow: hidden`, so the 7-option groups were cut off in a short window (verified: 289 px list, 560 px window, fully on screen).
- Place tools (single-click) + draft tools (wire/line/polyline, click-click or press-drag).
- **Multi-sheet:** `schematicSheets` + `activeSheetId` + per-object `sheetId`; Previous/Next/Goto Page.
- New boards seed a demo RC circuit; "Load Sample Circuit".
- **Wire tool snaps** to symbol pins / wire endpoints (and grid when Snap is on) so wires land exactly on pins.
- **Net labels hug the node they name** — placing `netLabel`/`globalLabel`/`hierLabel`/`netBusLabel`/`netFlag` snaps onto the nearest pin · wire end · junction and sits **10 px above** it (under `nets.ts` `CLUSTER_TOL` = 13, so the label still joins that net — proven via the Nets tab). With a place/draft tool armed, placed objects no longer swallow the click (`toolArmed` in `placed-objects.tsx`), so a label can be dropped straight onto a wire or part — previously that click just selected the object.
- **Icons are one-per-meaning** (`icons.tsx` raw dictionary + `hicons.ts` Hugeicon overrides — Hugeicon wins when present). Controls that read differently no longer share a glyph: `find` (lines + lens) vs `zoomin` (lens + plus) · `array` (solid + ghost copies) vs `grid` · `dAnnotate` (part + numbered badge) vs `pText` · `pBus` (trunk + branches) vs `pWire` · `pPolyline` (segments + vertices) · `dRule` (rule checklist, not a ruler) · **`dDrc`** (two coppers with the clearance gap measured between them — board rules are about spacing, so it no longer reads as a second tick beside `dCheck`) · **`tLenTune`** (one meandering net) vs **`tDiffLenTune`** (two rails, one meandering — pair skew, not single length) · `pDiffFlag` / `pKeepout` / `pPartMask`. The **supply family** (`pwrVcc · pwr5v · pwrN5v · pwrGnd · **pwrDgnd** · pwrAgnd · pwrPgnd`) draws the real schematic symbol each row places (DGND = the ground stack with a D mark, so it can't be read as plain GND in a list holding both), and the **label family** (`pNetLabel · pGlobalLabel · pHierLabel · pAttachedLabel · pPort · pOffPage`) draws each kind's own outline — tag · stadium · hexagon · tag-on-wire · port · sheet-edge arrow. Where the closest Hugeicon collided with another control, the key is left out of `hicons.ts` on purpose so the hand-drawn glyph wins (noted there). **A menu row's glyph is drawn for that row, including the parents**: `align` is a guide with two objects flush to it (both Arrange menus — it was `AlignSelectionIcon`, a bare frame, while its own six children read clearly · UIUX-38/59) · **`group` vs `ungroup`** — one boundary whole around two shapes, then broken with the shapes adrift (they shared `GroupItemsIcon`, so the two opposite commands were one picture · UIUX-40) · **`tRouteCorner`** (a mitred bend with the rounded alternative ghosted over it) vs **`dFillet`**, which used to borrow the same `pArc` (UIUX-56/61) · **`tRouteWidth`** (three weights of one line) vs **`tGloss`** (a smoothed track + polish mark), which both used to be the chain-link `wire` (UIUX-60) · **`dChamfer`** vs **`dFillet`** — the same square, one corner cut straight and one rounded, with the corner itself the emphasised stroke so the two differ at 24px (UIUX-61).

### Schematic connectivity, ERC, netlist & annotation (`nets.ts`)
- **Live netlist** — symbol kinds carry pin anchors (`SCHEM_PINS`); `computeNets()` union-finds pins + wire endpoints into nets, named from net-label / power / port symbols (same name merges) else auto `N1…`. Pure/derived — always reflects the drawing.
- **Auto-junction** — a wire ending on another wire's **interior (a T)** is electrically joined (on-segment union) and a **junction dot** is auto-dropped there on wire-finish.
- **Buses are bundles, not conductors** — a bus carries a `PREFIX[lo:hi]` name and **expands to member nets**: `computeNets` excludes buses from the electrical graph, so branch wires connect by member label (`BUS_D3` here = `BUS_D3` there, via same-name merge) and each member is its own net in the netlist. Bus membership (for ERC) is geometric (a pin/branch endpoint on the bus line).
- **Nets tab** (navigator) lists the live nets with object counts; clicking highlights the net (members via connectivity → `highlightedMembers`, since schematic objects have no stored `net`).
- **ERC** (`runErc` + `ERC_RULES` catalog) — a real rule engine over the live connectivity, emitting findings on the EasyEDA-Pro **5-level severity scale** (Note · Warning · Error · **Fatal**). Enforced rules: floating pins, free/dangling wire, single-connection net, label-not-connected, duplicate & unannotated & mis-formatted designators, empty Value, netflag/netport-needs-name, illegal net name (charset/length), illegal bus name, multiple-net-names-on-one-net, global-net short, port/flag/off-page name-vs-wire mismatch, unpaired differential pair, overlapping-unconnected pins (bare pin tips with no wire/junction join), **bus rules** (illegal bus name, bus-branch member naming `PREFIX[lo:hi]`, and netport/netflag/off-page ↔ bus name-match — a bus bundle legitimately carries many member names, so multiple-net-names is suppressed on it), and the **pin-conflict matrix** (Connection tab). Severities live in one catalog (`ERC_RULES`). The pin-conflict rule reads each pin's electrical type (`SCHEM_PIN_TYPES` / `POWER_PIN_TYPE` / `props.pinType`) and looks up the pair in `defaultPinMatrix()` — so two op-amp outputs = Error, Power↔Ground/OUT↔Power = Fatal, while normal passive nets stay clean (matrix default is Ignore; a No-Connect flag suppresses the net). Results show in the bottom **DRC/ERC tab** (Fatal/Errors/Warnings/Notes counts) via "Electrical Rule Check" / Design ▸ Run design check, **and on the canvas** (UIUX-81, `drc-markers.tsx`): each finding names the objects it is about (`ErcIssue.ids`, filled by `emit`), so the offending wire · pin · part · flag is **ringed where it sits** — a dashed circle sized to that element's real bounds and coloured by severity (Fatal · Error · Warning · Note), with the severity dot and its tooltip on the ring. A finding that names nothing keeps the small positional marker, and the bottom tab's **Show on canvas** turns the layer off. Verified against a sheet built to trip one rule per severity: overlapping pins (Fatal), an unnamed Netflag (Error), GND shorted to VCC (Warning) and an unannotated `R?` (Note) — 8 dashed rings, four distinct severity colours, and the shorted wire's ring 232 px wide against a symbol's 32. **Config-driven** — `runErc(objects, cfg)` reads the **Design Rules dialog** config (`state.designRules`, persisted per-project in the doc): a disabled rule is skipped, a re-severitied rule reports at the tuned level, and the pin-conflict matrix + its master toggle come from the config. The dialog (Save → `setDesignRules`) is the real tuning surface, not a stub. **Its shell is IDEEZA's own**: a category rail (Nets & connectivity · Components · **Agile Modules** · Pin conflicts) with per-category *on / total · checked* counts, a whole-config summary (`23 of 35 rules on` + severity chips), a rule filter, an **Only rules the engine checks** toggle and Enable/Disable-shown. Rules the engine doesn't implement yet carry a **“not checked yet”** badge (from `ERC_ENFORCED_ROWS`/`ERC_RULE_AT`, exported from `nets.ts` as the inverse of `ERC_TO_DIALOG`) so a toggle never pretends to matter. **The config contract is load-bearing** — `runErc` looks rules up by category + row index, so the dialog never reorders or filters the stored arrays; the search box filters only what is displayed and every row keeps its true index. **Every toggle is keyboard-operable** — the rule rows, the *Only rules the engine checks* filter and the pin-conflict master were `<span onClick>` around a painted box, so Tab never reached the controls that decide what the checker reports; they are `<button role="checkbox" aria-checked>` now (`CheckRow`), and the design-system `Checkbox` gained a `decorative` flag so the painted box inside a labelled control no longer announces a second, nested checkbox role (verified: 0 nested roles). Footer: Import/Export/Restore-defaults · Cancel (discards the buffer) · **Save & check now** (saves, then really runs `runErcCheck` and opens the results tab — the old “Verify Now” only switched tabs) · Save. *Bus rules validate names against `PREFIX[lo:hi]` and the netlist expands each member as its own net. Feature-blocked (not enforced): reuse-block rules (Net-reuse #1-3), unconnected-wire-name-visibility (#18), supplier-part match; library-guaranteed component rules are intentionally excluded.*

- **Phase 3 — Connectivity & free copper (`runConnectivity`):** copper that should carry a net (track/pad/via/region/fill) but is **unnetted** → "Free copper"; and same-net copper that doesn't all join geometrically (union-find over touching geometry, `TOUCH_TOL`) → "Disconnected net — N isolated sections". Both at Warning.
- **Phase 4 — Differential pairs + netlist mismatch (`runDiffPairs`/`runNetlist`):** per pair in `state.pcbDiffPairs` — **missing member** (one rail routed, the other not), **width** (track width vs the pair's target), and **length skew** (|len(netA)−len(netB)| vs `diffPairSkewMax`, default 0.5mm) — all at Warning; verified live against the default USB_D pair. **Netlist-mismatch** (`runNetlist`, Fatal for a schematic net absent on PCB, Warning for an extra PCB net) is implemented + unit-tested but **gated off live** in `runDrcCheck` — the Schematic→PCB convert renames nets to `N1…`, so a name comparison would flood every net as missing until the convert preserves net names.
- **Phase 5 — the manager lists are rules (#99)** (`runNetClasses` · `runEqualLength` · `runPadPairs`): a **net class** states the track width and via size its nets must have, an **equal-length group** the window every net must land in (`target ± tolerance`, mil), a **pad-pair group** its target spacing (±10%). Before this, `pcbNetClasses` / `pcbEqualLength` / `pcbPadPairs` were stored by their dialogs and read by **nothing**.
- **Pad-pair groups say what they really do** — adding or removing a pair writes the group immediately, so the dialog's old `Apply` (a toast) and `Cancel` (which reverted nothing) were theatre. The footer now reads *Groups save as you edit them* · **Check now** (runs `runDrcCheck` and closes to the results) · **Done**. ## 6. Coding conventions

- **Workflow — use the superpowers skills for code work.** Start any coding task by invoking **`/using-superpowers`**; follow its process flow — **brainstorming** before building a feature, **writing-plans** for multi-step work, **test-driven-development** while implementing, **systematic-debugging** for any bug, and **verification-before-completion** before claiming done. Don't jump straight to editing.
- **Real logic, never stubs.** No button that only `flashToast`s or sets a dead flag. Implement the actual behaviour (correct math — group rotate/flip pivots on the selection centroid; z-order reorders the objects array), then **verify in a real browser**. Be upfront about anything still incomplete.
- **`tsc --noEmit` must pass.** `data.tsx` is `@ts-nocheck` (pure data builders) — everything else is type-checked.
- **Store discipline:** pick `merge` vs `mergeWithHistory` deliberately (model change → history). Read via `stateRef.current` in event/async actions. New persisted state → add to the doc type + sanitizer + save effect.
- **One model:** route new placed things through `CanvasObject` + `placed-objects.tsx` rather than bespoke rendering.
- **Match the surrounding code** — comment density, naming, idiom. Reference files as `path:line`.
- Prefer editing the existing builders (`data.tsx`, `inspector-schema.ts`) over parallel systems.

## 7. UI/UX guidelines

- **Workflow — use `/ui-ux-pro-max` and `/impeccable` for UI/UX work.** Plan and build any interface, visual, layout or design-system change through these skills (they enforce the register, tokens and craft rules below). Reach for them on new surfaces, redesigns, polish passes, and design critiques.
- **Tokens only** — never hardcode color/spacing/radius/shadow. Use `--color-*`, `--spacing-*`, `--radius-*`, `--font-size-*`, `--elevation-*`, `--border-width-*`. Both **light + dark** themes (`data-theme` + `prefers-color-scheme`).
- **Brand = violet** (`--color-violet-600`, #7c2db9). Accent is for **selection / active / primary only** — not decoration. Restrained palette (product register).
- **The design-system `Checkbox` / `Radio` are real controls** (`components/ideeza/checkbox.tsx`) — they announce `role="checkbox"` / `role="radio"`, so they now also take focus (`tabIndex`) and activate on **Space/Enter** whenever they carry an `onChange`; they were mouse-only, which made every labelled row built on them (Sheet Border, Sheet Info fields, Zone reference, dialog toggles) unreachable from the keyboard. A `decorative` flag drops the role for the cases where the box is only the picture inside a labelled `<button role="checkbox">`, so no control announces itself twice.
- **Shared classes** (`pcb-editor.css`): `.ix-tool` (icon button), `.ix-row` / `.ix-mi` (list/menu row), `.ix-menu` / `.ix-submenu`, `.ix-tab`, `.ix-pill`, `.ix-btn`, `.ix-seg`. Reuse them; don't reinvent hover/active states.
- **Icons:** `<DsIcon name={...} size strokeWidth />` — resolves a Hugeicon first, falls back to the SVG-string dictionary.
- **Menus & dropdowns must never clip.** The editor is full of scroll/overflow containers → any flyout **portals to `<body>` with `position: fixed`** and **clamps into the viewport** (flip left near the right edge, shift up near the bottom). Anchor context menus at the cursor.
- **Earned familiarity** — behave like Figma / EasyEDA / KiCad / Linear; the tool disappears into the task. No invented affordances for standard actions.
- **Contextual disable, not stubs** — grey a control when its precondition isn't met (Copy needs a selection, Cross Probe needs a PCB link); light it up when it is. **Empty states teach** ("No nets yet — convert to PCB to generate").
- Motion 150–250 ms, ease-out; state feedback only, no decorative choreography.
- The Position/arrange panel is the reference for dense control layout: equal-size boxes on an aligned grid, segmented icon groups with hairline dividers.

## 8. Scope / direction


Building a **real, shippable product** in phases (schematic → PCB → routing/DRC →
manufacturing/export). The Schematic→PCB engine is **native in-app** (KiCad
export exists via `kicad-export.ts`, but conversion/placement/routing are our
own). Communicate concisely; keep changes tightly scoped to what's asked.

# UI/UX guidelines

Moved verbatim from `CLAUDE.md` §7 on 2026-09-29. The binding one-line rules are in [AGENTS.md › UI/UX hard rules](../../AGENTS.md#uiux-hard-rules); this guide keeps the full reasoning, the component notes and the recorded exceptions. Keep it current: [AGENTS.md › Keeping docs current](../../AGENTS.md#keeping-docs-current-required).

- **Workflow — use `/ui-ux-pro-max` and `/impeccable` for UI/UX work.** Plan and build any interface, visual, layout or design-system change through these skills (they enforce the register, tokens and craft rules below). Reach for them on new surfaces, redesigns, polish passes, and design critiques.
- **An opacity modifier does not work on a token colour.** Tailwind v3 can only inject alpha into a colour it can parse, and every DS colour is a bare `var(--color-…)`, so `bg-bg-page/60` compiles to **nothing at all** — no rule, no error, an invisible element. Four modal scrims and a destructive chip's hover were written that way and painted nothing. Reach for `bg-[color-mix(in_srgb,var(--color-bg-overlay)_62%,transparent)]`, or a token that already means what you want (a dialog's footer band is `bg-bg-subtle`, not the page colour at 40%). The same trap catches a colour key that does not exist: the preset's border colour is `DEFAULT`, so `bg-border-default` is also nothing — it is `bg-border`. Both are invisible in review and in the browser; grep the compiled sheet if you are unsure a utility exists.
- **Tokens only** — never hardcode color/spacing/radius/shadow/type. Use `--color-*`, `--spacing-*`, `--radius-*`, `--font-size-*`, **`--line-height-*`**, **`--letter-spacing-*`**, `--elevation-*`, `--border-width-*`. Both **light + dark** themes (`data-theme` + `prefers-color-scheme`).
- **Tokens are synced from the Figma variables, not guessed** — `color/card/border`, `color/badge/blue-*`, `color/focus/halo` and `letter/spacing/slight|wider` were missing, and `letter/spacing/caps`, `Elevation/1|2` (two soft slate shadows in light; the effect styles carry no dark value, so dark keeps its own), `color/text/blue` (blue-700) and `line/height/2xs` (14px) had drifted from the design system (synced 2026-09-25). A value the variables don't carry — a component's raw effect, say — is left out and reported, never approximated.
- **Style in classes, not `style={{…}}`** — the Brief and the video-jobs surfaces used to carry a palette object (`C`) and shared `inputStyle` / `textareaStyle` objects, so their colours never went through the preset and a reference to an undefined variable failed silently (Step 1's six `var(--color-border)` dividers never rendered). They are token classes now (`FIELD_CLASS`, `TEXTAREA_CLASS`); an inline style is left only where the value is data — a progress fill's `scaleX(p)`, the rail's measured offset, a row's colour from `buildRail`. Poster art (the storyboard frames, the review clip) is the two gradient tokens under a `--color-bg-overlay` scrim, since there is no third ramp and an agent does not mint one; the QR plate alone keeps `--color-white` / `--color-gray-900`, because a theme-flipped code does not scan.
- **Line height pairs with font size** — `text-md` wants `leading-md`; `leading-relaxed` is the multi-line prose variant for any size. (The Figma collection offsets the two scales — `line/height/5xl` sits with `font/size/4xl` — so the pairing is made explicit in `tokens.css`.) Letter spacing: `tracking-tight` for display type, `tracking-slight` for a display heading a step under tight, `tracking-wide` for label type, `tracking-wider` for a value bubble, **`tracking-caps`** (1.5px — the design system's own value; it was 0.5px) for the uppercase micro-labels the panels are full of. An arbitrary `leading-[19px]` / `tracking-[0.5px]` is now a token violation.
- **A pad is copper, not a layer** — `--color-pad-copper` / `--color-pad-mechanical` are the material colours a land pattern reads in (the footprint editor, its previews and the 3D placement all share them). `--color-pcb-top-copper` is red because the *board* locks Top = red; that identity says nothing on a single part.
- **`text-tertiary` is a reading colour, not a whisper** — it labels half the panels in this app, so it has to clear 4.5:1 on the surface behind it. Light was `gray-400` (**2.34–2.56:1**, a real WCAG 1.4.3 failure wherever it carried words) and is now `gray-600`; `text-disabled` steps down to `gray-400` and `icon-secondary` to `gray-500` so the three stay distinguishable, and dark mirrors the same order. Disabled text is deliberately left below 4.5:1 — WCAG exempts inactive controls, and lifting it would stop it reading as disabled.
- **`Segmented` vs `ButtonGroup`** — `ButtonGroup` announces `role="tablist"`: right for switching *which view you are looking at*, wrong for choosing a value, because a screen reader then calls the options tabs. Use **`Segmented`** (`role="radiogroup"`) when the choice *is* the data — a unit, an angle, a mode.
- **Weight matches urgency** — `Banner`'s `attention` tone blocks Next, so it keeps a filled, bordered box; `good` is the *absence* of a problem, and a full-width saturated slab announcing that nothing is wrong competed with the step heading (in dark it was green-900 behind a green-400 edge). It keeps the tick and the success colour and gives up the fill and the border. Same rule on a chosen radio card: the border and the mark already say which one is on, so the card no longer fills with brand.
- **A card does not go inside a card** — `/parts` had bordered item cards sitting in a bordered, filled panel, which is depth for its own sake. The controls keep their grouping with a hairline under them and the cards sit on the page. (Splitting the search row from the filter row also stranded the two filters in an empty strip once the panel stopped being a card; search, filters and the visibility tabs are one band now.)
- **One recorded exception: the 3D model panel is drawn as its Figma frames are** (decision D2, 2026-09-25) — caps overlines on each rail section and 10px caps-tracked hint lines, where the rule below would lift them. Everywhere else the rule holds.
- **10px is for a micro-label, not for reading** — `--font-size-2xs` is the scale's smallest step and it had spread to card facts, hints, notes, status chips, the editor toolbars and the step rail. Navigation and anything with sentences moved up: prose and meta to `sm` (12px), uppercase micro-labels and control labels to `xs` (11px). `/parts` went from 48 elements at 10px to none.
- **Prose gets a measure** — body copy is capped at `62ch` (measured at ~74 characters a line with the real typeface, inside the 65–75 band). Before this the step headings ran 640–660px of 14px type, and a note on the part page ran the full 900px at 10px.
- **The em-dash was doing a full stop's job** — the flow's copy leaned on it in almost every sentence, which is a recognisable machine-writing tell. Rewritten as sentences where it joined two thoughts. Kept: the `Label — state` tooltip shape and the `—` empty-value placeholder, both compact conventions rather than prose.
- **`Segmented` never stretches** — it is `inline-flex`, but as a child of a column flex container `align-items: stretch` still pulled a two-option unit picker to 715px. `w-fit self-start` lives in the atom, so no call site has to remember.
- **A unit adornment is a unit, not a button** — `TextInput`'s `suffix` had a divider and a filled background, so every dimension field ended in something that looked pressable and three stacked read as a column of controls. It is quiet text inside the field now.
- **Brand = violet** (`--color-violet-600`, #7c2db9). Accent is for **selection / active / primary only** — not decoration. Restrained palette (product register).
- **The design-system `Checkbox` / `Radio` are real controls** (`components/ideeza/checkbox.tsx`) — they announce `role="checkbox"` / `role="radio"`, so they now also take focus (`tabIndex`) and activate on **Space/Enter** whenever they carry an `onChange`; they were mouse-only, which made every labelled row built on them (Sheet Border, Sheet Info fields, Zone reference, dialog toggles) unreachable from the keyboard. A `decorative` flag drops the role for the cases where the box is only the picture inside a labelled `<button role="checkbox">`, so no control announces itself twice.
- **The design-system `Select` escapes its scroll container** (`components/ideeza/select.tsx`) — the options panel portals to `<body>` with `position: fixed`, measured off the trigger, flipped above it when the rows don't fit below, clamped into the viewport and capped at 280 px with its own scroll; an ancestor scroll or a resize closes it, since the anchor it was measured against has moved. It lives inside the package flow's `overflow-x-auto` tables and the PCB settings' scroll panes, where the absolutely positioned panel was cut to a sliver. Verified over CDP: portalled to `<body>`, flipped above a trigger 40 px off the viewport floor, wholly on screen, commit by click and by ArrowDown/Enter, Escape and an ancestor scroll both close it.
- **`Segmented` keeps the radio-group contract it announces** (`components/ideeza/segmented.tsx`) — it called itself a `radiogroup` while every option was a Tab stop and the arrows did nothing. It is one Tab stop now (roving tabindex on the chosen option), Arrow Left/Right/Up/Down move the choice and wrap, Home/End jump to the ends, and selection follows focus. The chosen option paints **brand-subtle fill + brand text**, the treatment `ButtonGroup` and the PCB right panel already use, instead of a solid brand slab that spent the accent on a control that is not the page's primary action.
- **One `Banner`, four tones** (`components/ideeza/banner.tsx`) — `good` · `attention` · `info` · `error`, with an optional `title` that puts the tone in the glyph and the page's own ink in the words. The build page used to carry a second banner with its own tone table and its own padding; `build-status.tsx` maps its state names onto the atom's tones, so the queue, the partial failure and the system failure all come from one control.
- **The design-system `Select` is a real listbox** (`components/ideeza/select.tsx`) — the trigger announces `combobox` and the panel a `listbox` of `option`s, ArrowDown/Up walk the options (wrapping), Home/End jump to the ends, Enter/Space commit, Escape closes and returns focus to the trigger, and Tab closes it on the way out; the active option is named by `aria-activedescendant`, so focus never leaves the trigger. The options used to be `<div onClick>` with no role and no key handling, which made **every filter and form field built on this component mouse-only**. Hover and the keyboard share one highlight, so arrowing looks like pointing.
- **The design-system `Select` trigger draws its border** (`components/ideeza/select.tsx`) — the reset's `button { border: 0 }` sets `border-style: none`, and `border` only sets a width, so every `Select` drew no edge and read as a line of text. The trigger names `border-solid` now (as `SelectMenu` already did), at `--border-width-1` in `--color-border-default`, stepping to `--color-border-strong` on hover and `--color-border-focus` on keyboard focus. **Any bordered `<button>` has to name its border style.** Verified in both themes on the package Symbol Creator, the schematic Properties panel and PCB Settings ▸ Schematic Symbol.
- **A symbol kind with no glyph is a defect, not a fallback** — `GLYPHS` had no `ic`, `connector` or `transistor`, so `glyphFor` returned its generic dot: placing an ESP32, a USB-C connector or a MOSFET from the catalogue drew a **black circle on the sheet**, and 8 of the 15 catalogue rows previewed as one. All three are drawn now, in the same register as the rest (centred on 0,0, `currentColor`, ~1.6 stroke): an IC body with its pins and pin-1 mark, a connector shell with its contacts, and a BJT with the emitter arrow. The geometry itself moved to **`lib/pcb/glyphs.tsx`** so a surface that only wants to *draw* a symbol can import it without pulling in the editor's store; `placed-objects.tsx` re-exports it, so the canvas is unchanged.
- **Shared classes** (`pcb-editor.css`): `.ix-tool` (icon button), `.ix-row` / `.ix-mi` (list/menu row), `.ix-menu` / `.ix-submenu`, `.ix-tab`, `.ix-pill`, `.ix-btn`, `.ix-seg`. Reuse them; don't reinvent hover/active states.
- **Icons:** `<DsIcon name={...} size strokeWidth />` — resolves a Hugeicon first, falls back to the SVG-string dictionary.
- **Menus & dropdowns must never clip.** The editor is full of scroll/overflow containers → any flyout **portals to `<body>` with `position: fixed`** and **clamps into the viewport** (flip left near the right edge, shift up near the bottom). Anchor context menus at the cursor.
- **Earned familiarity** — behave like Figma / EasyEDA / KiCad / Linear; the tool disappears into the task. No invented affordances for standard actions.
- **Contextual disable, not stubs** — grey a control when its precondition isn't met (Copy needs a selection, Cross Probe needs a PCB link); light it up when it is. **Empty states teach** ("No nets yet — convert to PCB to generate").
- **Animate `transform`, not `width`** — a progress fill is `width: 100%` scaled with `scaleX(p)` from its left edge inside a clipping track (the build rows, the Brief's render bars, the regenerate flow's and History's quota bar; likewise the Brief's switch knobs slide by `translate-x` and the voice waveform's 78 bars scale by `scaleY`): an animated width re-lays the row out on every tick, a transform stays on the compositor. The sidebar collapses at once rather than animating its width — a panel toggle is a state change, and animating it re-laid the whole page out on every frame.
- Motion 150–250 ms, ease-out; state feedback only, no decorative choreography. **One deliberate exception**: a small light travels along the top of the dashboard hero (`.ix-hero-sweep` in `globals.css`) — one compact blurred lobe crossing the top edge over 22 s, fading in as it enters and out as it leaves so the loop has no seam. The wash under it stays **still**: it is the ground the headline sits on, and a whole surface breathing is a room with a flickering bulb. The hero is the one surface here that is a front door rather than a tool, the light moves on `transform`/`opacity` alone, and nothing below it moves. The glow layer is **900 px tall on purpose**: `overflow-hidden` is there for the travelling light, which crosses ±42 vw and would otherwise widen the page, but at the wash's own height it cut the blur off at 420 px while it was still 33 levels above the page colour — a hard rule straight across the hero. Measured down the middle: it now falls 59 → 32 → 28 → 26 and reaches the background by ~520 px, with no step anywhere. Two traps it was written around: the Y offset has to live **inside** the transform, because the animation writes that whole property and a `-translate-y` utility beside it is discarded on the first frame; and the resting values have to live **on the class**, because the global reduced-motion rule *ends* an animation rather than holding a frame of it — the element falls back to its own styles, so at rest the light is `opacity: 0` and a maker who asked for calm gets exactly the still wash that was there before.
- The Position/arrange panel is the reference for dense control layout: equal-size boxes on an aligned grid, segmented icon groups with hairline dividers.

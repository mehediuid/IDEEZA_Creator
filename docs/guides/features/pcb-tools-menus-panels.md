# Features — PCB module: toolbars, menus, panels & geometry

Part of the feature inventory ([index](README.md)). Moved verbatim from `CLAUDE.md` §5 on 2026-09-29. Keep it current: [AGENTS.md › Keeping docs current](../../../AGENTS.md#keeping-docs-current-required).

## Top toolbar — all tools real
- **Schematic toolbar** (`SCHEM_ESSENTIAL`): **Find & Replace** (leads the row — it used to sit last, behind four zoom/fit lenses, where it read as one more zoom) · **Save** + the save chip · **ERC** (a **named toolbar control** — icon + label, no fill, no border, no pill, brand ink only — with its own `dErc` glyph: the schematic's own term, since “Design Rule” pointed at the board's DRC, and the sheet's main check should be findable. It used to be a brand-tinted capsule, which read as a button and competed with the page's one solid CTA) · **Agile Module** │ Undo · Redo │ Zoom In/Out · Fit-Screen · Fit-Selection │ **Grid-style picker** · **Snap** · Grid-size · Unit │ Find. **The Schematic→PCB hand-off is the mode switch, not a button** — the old **Convert to PCB** pill was a second door to the same outcome (its confirm only called `setMode("pcb")`, and the tab converted by itself anyway). Clicking `PCB` on the first entry now opens the **convert plan** — a dialog that says exactly what it will do before it does it: `N parts get a land pattern, connected by N airwires across N signal nets`, the **list of every footprint** (Designator · Symbol · Footprint — `R1 · Resistor · R_0805`), and the honest notes — which **power nets stay off the ratsnest**, how many parts the converter had to **name itself**, which part-like symbols have **no land pattern yet** (crystal · transistor), and that **tracks aren't routed** (Auto Route does that). The list comes from `ConvertPlan`, built in the same pass `convertSchematicToPcb` uses to do the work, so the preview can't promise something else. Cancel leaves the sheet untouched (verified: 11 objects before and after); Confirm converts and lands on the board (`pendingMode`); a second visit just switches, because there is nothing to convert. The tabs now say what they do on hover (`Lay out the board — the schematic is converted to footprints and a ratsnest on the way in`) and carry `aria-pressed`; the deliberate re-sync is **Design ▸ Generate PCB**, which really re-runs the converter. `buildModeTabs` also stopped handing out paint (`C.primary` / `'#fff'`), like `buildLeftTabs`. **Grid is a real 3-mode control** (`state.gridType` → Grid · Dot Grid · No Grid): both canvases draw ruled lines, dot lattice, or nothing, and the choice persists with the document. Snap lights up from `snapEnabled`. **Agile Module** opens the part library on its own tab (`openPicker`).
- **The panel header is one row on one baseline** (`left-panel.tsx`) — the two destinations, then the assistant, then the collapse chevron: **every box exactly 28 px tall, one radius, 6 px apart**, on a 45 px row closed by a hairline. The current view is a **filled chip** (`--color-bg-subtle`, which steps lighter than the gray-900 panel in dark and greyer than white in light, so it needs no border) and the other tab is plain text — no track, because a bordered track holding a smaller bordered pill put two rounded rectangles inside each other and left the pill 22 px against 28 px controls. A chip rather than an underline: the sub-tab row directly below is already underlined. The chips **size to their label** and the tools hug the right edge, so the spare width becomes the gap between destinations and chrome. Both labels are **one weight** (a 700/500 swap changed their width, so the tabs jumped as you switched) and never wrap; `Project Design` truncated at the panel's real width and echoed the *Project design* sub-tab below, so the tab is **Project**. The paint left `buildLeftTabs`, which used to hand back `bg: '#fff'` — a slab no theme could touch. The header stack now shares **one 14 px content inset** (it was ragged: 10 px tab row, 16 px sub-tabs, 14 px search), and `PANEL_LIMITS.left.min` moved 208 → **240 px**, the width at which this header still reads.

- **The AI assistant sits in the left panel's tab row** — a 34×28 bot button beside Project / Library (it swaps the same panel body, so it belongs with the destinations, not in a full-width bar above them). It is the **one accented control** in that panel and carries the brand's own gradient: `--gradient-brand` / `--gradient-ai` + `--glow-ai` are now **real tokens**, per theme (the app had `linear-gradient(135deg,#b06be0,#7c2db9)` hand-written at each call site, so it couldn't follow the theme). The craft is static, not animated — gradient fill, a 1px lit top edge (`::before` inset highlight), and a violet glow that lifts it off the panel, which is what makes the eye land on it; hover raises it 1 px and strengthens the glow, and **open** presses it in and retracts the glow so “showing” never looks like “available”. An earlier version breathed a halo forever; decorative motion that signals no state change is banned in this register, so it went. Picking a tab while the chat is showing now **closes the chat and shows that tab** — the click used to change `leftMain` invisibly behind the chat, so the tabs read as dead.
- **The assistant panel is built for a 270 px rail, not for a phone** (`components/code/ai-chat.tsx`, shared by PCB · Blockly · Code IDE). It was a two-column bubble chat: a solid violet block for your message, a grey bubble for the reply, both capped at 88% so half the panel went to whitespace. Now the thread is **asymmetric** — what you asked is a tinted, brand-bordered block on the right; what the assistant said is **plain prose across the full width** — and every part earns its place: a header naming the module it knows (*Board · Blocks · Firmware · Model · Assembly assistant*, so it isn't a second copy of the host's "AI Assistant" label) with a **New thread** button that greys out when the thread is already new; **opener chips** on first run, drawn from queries the reply engine really answers, so a click can't dead-end; a **composer that is a textarea** (grows to four lines, Enter sends, Shift+Enter breaks, and it says so) with a placeholder that names the module (*"Ask about your board…"*, not *"your program"*) and a **send button that is really disabled** until there's something to send; a **"Thinking…" indicator with animated dots** instead of a literal `…` bubble; and when the model actually changed the editor, a **green receipt** ("Applied") separate from the prose, because said and did are not the same thing. The thread is a `role="log"` + `aria-live="polite"` region, motion is 180 ms with a `prefers-reduced-motion` opt-out, and the cross-module hand-off button reads in the app's own language (*"Open PCB Design with this →"*, replacing mixed Bengali/English strings).
undo/redo, zoom, **Fit All/Section/Area** (real content/selection fit), grid, snap, **align L/R/T/B**, **distribute H/V**, rotate, flip, bring-to-front/send-to-back, **Save** (real `localStorage` write), Flip Board, managers, export, DRC, annotate, convert. No `flashToast`-only stubs.
- **Suture vias are generated, not stamped** (`suture-vias.ts` `planSutureVias` + `generateSutureVias`) — **Insert ▸ Suture Vias carries the shape you draw** (UIUX-95): **Rectangle** is dragged, **Polygon** is clicked corner by corner (Enter · double-click · first vertex closes it), and **Line** draws the path a **via fence** follows — vias walked along the polyline at the stitch pitch, which is a different thing from a lattice poured into an area, so the dialog says *fence* there and the planner spaces along the path rather than filling a box. The drawn geometry lands in `state.sutureShape` (`suture:rect|polygon|line` tools, `parseSutureTool`) and opens the dialog on it (target: **drawn shape** · selected region · whole board; net; staggered/grid; spacing; via size; drill; edge clearance) and drops **real `via` objects** inside the region (point-in-polygon + distance-to-edge clearance), so the DRC, the 3D view and the exporters see them like any other via. The dialog's count and the placed result come from the **same planner**, so the preview can't lie (verified: `Will stitch 165 vias` → toast `Stitched 165 vias on GND`, objects 3 → 168), it explains an empty plan instead of showing 0 (`No room inside that region — try a smaller pitch, via size or edge clearance`), and the footer removes the ones already there (`Remove 165 existing` → back to 3). The old row was a flat action that jumped straight to placement with no shape choice, and before that a tool that stamped a 5-via glyph; that palette row is gone, and the right panel's Place/Remove-Suture-Vias action opens the same dialog — one home. *(Copper regions are still fixed-size stamps, so region stitching only fits when the via size + clearance are small; whole-board is the practical target until regions can be drawn at size.)*
- **Import Image is a real import, on both canvases** (`ImportImageModal`) — Project ▸ Import ▸ Image… **and Insert ▸ Image in either mode** (UIUX-83: the schematic row armed a place tool that stamped an image object with no file behind it, so the sheet had no import dialog at all) reads a PNG/JPG/SVG/WebP, shows its natural size, sizes it with an aspect lock, and can **reduce it to 1-bit ink** (optional smoothing over the luminance, then luminance vs threshold + invert, done on a canvas — ink stays opaque, everything else becomes transparent so the board shows through). The dialog is **mode-aware**: the board picks a target layer (silkscreen by default) and sizes in **mil**; the sheet has no layers, sizes in **mm** (converted to canvas units on place, not labelled px as mm) and states the same reduction the other way round — **Place original (bitmap)**. **The reduction is shown, not promised** (UIUX-99): ticking it opens a *Silkscreen conversion* section with the original and the converted result **side by side** plus **Threshold** and **Smoothing** sliders, both re-running the conversion live — and Place writes those very pixels, since preview and commit call one `toMono`. Verified: threshold and smoothing each change the written image, and the placed object's data URI is byte-identical to the pane's. Confirm places an `image` object carrying the data URI, and `placed-objects.tsx` draws the **real bitmap** (`ImageObject`) instead of the picture-frame glyph it used to. Verified end-to-end with a 24×12 test PNG: natural size read, placed 160×80 (aspect kept), mono conversion produced a new PNG, and the ink half renders while the other half shows the board. *(Board SVG/PDF/Gerber exports don't rasterise images yet — the object is real on the canvas, the exporters are honest about not carrying it.)*
- **Board cutouts are real** (`cutout` in `DRAFT_TOOLS` → `finishWire`) — Edit ▸ Cut out board area arms a tool you **drag** (two corners); the dialog used to promise “draw a rectangle … the area will be removed” while `cutout` was in neither `PLACE_TOOLS` nor `DRAFT_TOOLS`, so arming it did nothing. The object stores its top-left in `x/y` and its extent in `width/height` — one source, so the Properties panel's Rectangle Outline binds (`obj:width`/`obj:height`) both **read and resize** it (verified: 108 → 220 px). It renders as removed material (hatched, Board-Outline colour), becomes a **real hole in the 3D slab** (`PcbSlabMesh` switches from a box to an `ExtrudeGeometry` shape with holes when cutouts exist — no CSG dependency), and is written as a board edge into **DXF** (OUTLINE layer), **PDF** and **SVG**. *(STL/OBJ still export the slab as a solid box — a mesh boolean needs CSG, so it is left honest rather than faked.)*
- **Board-mode placements carry `scope: "pcb"`** (`placeObject` / `finishWire`) — they used to be left unscoped, and the 3D scene + exporters select on `scope === "pcb"`, so a manually placed pad/via/track/region was invisible to both while the DRC saw it. Now what you place on the board is what the 3D tab and the export files show.
- **The export dialogs' own controls reach the file** — they used to be decoration: **DXF** (`buildDxf(m, opts)`) now honours **unit** (mm/inch), **scale**, **copper side** and a real **Include** set (outline+cutouts · tracks · pads · vias+drills · component outlines), with `Range` = whole board or the selection (`collectPcbModel(state, {onlySelected})`), an editable filename and a summary that counts what will be written (verified: unticking Component outlines dropped `COMPONENTS` from 8 → 0 in the file). **Export board artwork** (UIUX-79, `DocumentModal` + `buildSvg`/`buildPdf(m, opts)`) — it was a single column of five labelled radio rows in EasyEDA's own vocabulary (*File Type · Theme · Line Width · Range · Output*) with nothing to look at, so you picked an ink and a stroke policy blind and found out by opening the file. It is now **the two-pane shape the sheet export uses** — calibration left, a **live preview right that renders the very SVG the export writes** (re-rendered on every change, captioned with the board's real mm size) — in the board's own language: **Format** (PDF · PNG · SVG) · **Range** (Whole board · Selection (N), disabled with the reason when nothing is picked) · **Ink** (As drawn · White on black · Black on white (print)) · **Copper strokes** (True widths · Hairline) · **Sides** (Both on one sheet · Top and bottom separately, where the preview says it is showing the top). Every control still reaches the file (verified: black-on-white SVG per side wrote `board-top.svg` + `board-bottom.svg` with the green substrate gone; Export writes `board.pdf`). Previously only File Type did anything and the filename was hardcoded. **BOM** is IDEEZA's own shell: pick from real columns (No · Qty · Designator · Comment · Value · Footprint · Package · Side · **Manufacturer · MPN · Unit price · Extended · DNP** · Description). **Sourcing is its own set of fields** (UIUX-78): `MPN / Supplier` was one lumped column, `Description` printed the *manufacturer* so it never held a description, and there was no price at all. Unit price is looked up from the catalogue row the part was placed from (matched on MPN) and left blank when unknown — an invented number in a BOM is worse than an empty cell; **Extended** is qty × unit, so a grouped line shows what that line costs. Value and the sourcing columns are **on by default**: a BOM you can assemble from but not re-order from is half a BOM, sort by any of them, and **group identical parts into one line with a quantity**; the on-screen preview *is* the file (one builder), and **XLSX is deliberately absent** with the reason stated — the old dialog previewed a hardcoded five-row table, always exported the same five columns (Manufacturer permanently `-`) and wrote CSV when you picked XLSX.
- **Gerber export is per layer** (UIUX-100, `GerberExportModal` + `GERBER_LAYERS`) — the dialog was one ambiguous `board.gbr`, an RS-274X/D format choice with only one format behind it, and three blanket toggles. It is now a **checklist built from the board's own layers**, grouped the way a fab reads them (Copper · Silkscreen · Solder mask · Paste mask · Mechanical · Drill) under IDEEZA's own names, with the editor's visualization layers deliberately absent; it states the **real stackup** (and names inner copper that carries objects but isn't in the two-layer exported board yet, rather than dropping it silently); the **file list is generated from the same selection the request sends** (`board-F_Cu.gbr`, `board-PTH.drl`, …, zipped as `<name>-gerbers.zip`), so what it lists is what the zip holds; and the format choice is gone. The selection reaches the exporter for real — `exportGerberViaKicad(doc, {layers, drill, name})` → `--layers` on `kicad-cli pcb export gerbers`, drill export skipped when unticked, board file named so the Gerbers carry the chosen prefix. Fixed on the way: SMD pads referenced `F.Paste`/`B.Paste` but the board file never declared them. Verified: 11 files listed, unticking a layer or the drill drops exactly its files, the name field renames all of them, and Export is disabled with nothing ticked.
- **Exports generate real files** (`exporters.ts`, `glb-export.ts`): **Gerber** (server kicad-cli → zip, per-layer as above) · **BOM** (CSV) · **Pick&Place** (CSV/TXT/JSON) · **DXF** (R12) · **SVG** · **PDF** (hand-rolled vector) — all three draw the **real board edge** (`ExportOutline`: rect · circle · polygon, from the drawn outline object) instead of assuming the `pcbBoard` rectangle · **PNG** (2D SVG raster; 3D via `export3dPng` canvas capture) · **Design files** (UIUX-82 — Export ▸ Design files opens a dialog with **Schematic · PCB · 3D** and writes exactly what you tick: the sheet as SVG, the board as SVG, the model as GLB; a part that doesn't exist yet disables itself with the reason instead of writing an empty file. The row used to fire `board.glb` the instant it was clicked.) · **3D STL/OBJ** · **schematic sheet PDF/PNG/SVG** (the Export Sheet dialog — `captureSchematicSvg(opts)` + `rasterizeToPng` + `buildSheetPdf`) · **board GLB** (`exportBoardGltf`, the editor menus' **Design files** row · UIUX-30 — the 3D view's Export menu still names each file it writes). *Sheet images capture the live sheet — each placed object's rendered `<svg>` is cloned with computed paint baked in (so `currentColor`/CSS vars survive) and wires, which are `<line>`s in one overlay `<svg>`, are placed via their screen CTM; the app's own background is used, so the picture reads the way the editor does. No second copy of the symbol geometry to drift.* *GLB builds a throwaway three.js scene from `derivePcbScene` — the same derivation the 3D tab renders — and serialises it with three's `GLTFExporter` (glTF 2.0 binary, meshes grouped Board / Copper / Components, no new dependency). It refuses honestly when there's no board yet.* *(STEP intentionally omitted — needs a CAD kernel; no stub. The **Delete Objects** dialog Confirm now really deletes per checked category — `deleteObjectsByCategory` + `del-objects.ts` `delCategoryOf`.)*
- **PCB/2D top toolbar = the board's own quick row** (`PCB_ESSENTIAL`): **Save** (it heads the row, where the schematic bar carries it, so the two line up · UIUX-13) │ **DRC** — a named control (icon + label, brand ink, no fill/border) in the slot the schematic bar gives **ERC**, so the two checks mirror each other across the views; it also swapped the generic tick (`dCheck`) for **`dDrc`**, the clearance gap DRC actually measures (UIUX-52) │ Undo · Redo │ Fit-All · Grid-style · Snap │ **Pad · Via · Fill Area · Board Outline · Routing · Ratsnest** (UIUX-85 — Board Outline arms the rectangle and Routing the single track; the other shapes and the diff-pair/tuning rows stay on the palette's flyouts, which a toolbar button can't carry) │ Auto Route │ **Save + the save chip** │ Grid-size · Unit, plus the "…" overflow. The **save chip** is the schematic's (`state.saveState`, real local write, no fake cloud) — verified reading `Saved 09:43 PM` on the board bar. **Auto Route** got a glyph that reads like auto-routing (two pads + a path that finds its own way); the old one was a gear-like circle with spokes.
- **The library window is a library, not a grid of stamps** (`library-panel.tsx`) — cards **auto-fit** the panel (`repeat(auto-fit, minmax(...))`) with a density switch, so a wider panel means bigger cards (verified 257×96 ↔ 128×62); each card previews the **real placed geometry** through `glyphFor` (the hand-drawn `SYMBOLS` map is gone — one source for a symbol); **hover** lifts the card, tints its border and reveals a **Place** pill with a tooltip that names what a click does (`Chip 0805 (R/C/L) · 0402 · fp0805 — click for details, double-click to place`); and a **click no longer places behind your back** — it opens a **detail strip** (bigger preview, group, variant, what kind it will place, Place button), verified: clicking left the board untouched (7 → 7 objects) and the strip's Place added one (7 → 8). Double-click still places directly. **The preview is sized by the reader, not by the panel** (UIUX-73) — the All-Library verified-parts result had its symbol, footprint and 3D previews squeezed into a fixed 96 px strip of 56 px thumbnails, so neither a land pattern nor a symbol could be read. That column now carries a `role="separator"` drag handle (pointer, ←/→ by 16 px, Home/End to the clamps, 96–320 px) and the three previews scale with it; the width persists with the document. - **The All Library is the real catalogue** (`AllLibraryFlyout` + `part-catalog.ts`) — the rows are `allParts()` (the system catalogue + the user's own Project ▸ New ▸ Part rows), not demo data: real MPN · manufacturer · features/package per row, the row's icon is the **real symbol it places** (`glyphFor`), and the **sidebar tree is derived** from the same list (family → package with live counts — it was a hardcoded junk tree) so picking a category really filters the results; the sidebar search filters that tree. Selecting a row opens **real previews** — the symbol glyph on the sheet ground and the package's **land pattern on the board ground**, honest ("No land pattern for SMD-53 yet") when none exists — and a detail strip with the row's real package/stock/unit-price and a **Use button that places the part** exactly like the picker (next free designator, `props.mpn/package/manufacturer`, Recent updated); double-click on a row places too. ## Boolean / Combine geometry (`shape-boolean.ts`)
Union · Intersect · Difference · XOR on shapes/copper-regions — each shape → polygon, rasterised, combined per-op, traced with marching-squares → a real filled `points` polygon (holes via even-odd fill).
**Corner ops** (`chamferRing` / `filletRing` + `applyCornerOp`) — Edit ▸ Add Chamfer / Add Fillet rewrite the real ring of every selected shape: a straight bevel, or a **true tangent arc** (centre on the bisector at `r/sin(θ/2)`, tangent distance `r/tan(θ/2)`, sampled in 8 steps). Apply used to be a `flashToast` with the size going nowhere. The trim is clamped to half of each adjacent edge so an oversized value can't fold the shape inside out, collinear vertices are skipped, and the toast reports the clamping (`Chamfered 1 shape · 4 corners clamped to fit`). Eligibility is `isCombinable` — the same shapes Combine accepts — and the dialog states it live (`Will apply to 1 shape`), with Apply disabled when nothing qualifies. Verified: fillet r=5 → 36-vertex arc polygon, chamfer 40 → 8 vertices + clamp report, both undoable.

# Features — platform, projects & network

Part of the feature inventory ([index](README.md)). Moved verbatim from `CLAUDE.md` §5 on 2026-09-29. Keep it current: [AGENTS.md › Keeping docs current](../../../AGENTS.md#keeping-docs-current-required).

## Platform & shell
- Global sidebar nav (Home · History · My projects · Parts & agile module · Explore marketplace · Innovations · Messages · Blog); top bar with search, profile dropdown, plan badge, Tutorial / Tour guide / Help / Report. **At phone width the sidebar is a drawer** (`sidebar.tsx` `MobileBar` + `SidebarDrawer`): below `md` a 56 px bar carries the menu, the mark and search, and the menu opens the same sidebar body over the page with a backdrop, Escape, focus held inside and handed back on close, closing itself on arrival at a new page (it remembers the page it was opened on, so no effect is needed). It used to stay open at 280 px beside every page, leaving the page 120 px — the home headline broke a word a line and the chat's canvas was off the screen (verified at 400 px: every page is 400 wide with nothing past the edge).
- **⌘K command palette** (`dashboard/command-palette`); light/dark theme (`theme-provider` + toggle).
- **`/parts` — Parts & Agile Module** (`app/(dashboard)/parts` + `components/parts/parts-library.tsx`, from the `feat/parts-agile-module` branch): the part catalogue, the captured Agile Modules and the packages the maker has authored, on one section rail over a dense list — the real flow for this destination. `/parts/new` is the New Package authoring wizard and `/parts/<id>` one part with its land pattern. *(An earlier branch put a per-build bill-of-materials index on this route; it was removed on the merge rather than left as a second parts destination — a build's BOM lives where it is produced, on the build's own Parts tab at `/build/<id>?tab=parts`, which the project page links as **Bill of materials**.)*

## Add Network & Connection Map (`lib/network`, `components/network`, Figma `HDtWAU2PSbjQKlEWgHI3ev` · `44533:123190`)
Built to the spec `docs/superpowers/specs/2026-09-24-add-network-design.md` (decisions D1–D12): Figma supplies the requirements, the app supplies the look.
- **The Add Network wizard** (`add-network-dialog.tsx`) — one dialog, five steps (Setup · Method · Connect · Review · Done) with a stepper, Back on every step and a *Discard this network?* confirm once there is progress. **Setup**: the four goals (Control all via 1 App · Products talk to each other · Both — app + direct · Cloud-only data sync) and the project's products as cards with a chip derived from the build's parts (`ESP32-S3 · Wi-Fi + BLE` — MCU plus the radios the part names imply; *No parts listed* when there are none), *N selected · M not included*, and a gate (≥1 product, ≥2 for the two local goals). **Method**: AI Auto-Map or Manual Canvas and the three-questions note. **Done**: *Network created*, a line that says *saved* (never *live* — D4), the 09b variant when no Cloud Name was entered, product → role, **Close · View Network** (D2, busy *Opening…*).
- **AI Auto-Map is a real model call with an honest fallback** (`api/network/automap` + `planner.ts`) — the products (names, descriptions, parts) and the goal go to the keyless Pollinations `openai-fast` model on its OpenAI-shaped endpoint with low reasoning effort (≈12 s for four products, under 30 s for six; the plain endpoint took 30 s and wrapped the answer in its reasoning), 45 s timeout. Every proposed link is validated against the boxes on the map and the three questions' own values and dropped, never repaired (`validateAiLinks`); a hub product the AI routes others through is moved to the middle column (`arrangeFor`). No valid link → the **rule planner** (the Figma Role-rules table read backwards: sense + act → two-way, sense → reports, act → is told) draws it and the banner says so. The proposal is reviewed as a list with the roles it produces before the canvas opens (Figma 04).
- **The connection canvas** (`map-canvas.tsx` + `map-editor.tsx`) — HTML boxes (product · MQTT Broker *C* · App *A*) and SVG arrows on one pan/zoom plane (wheel pans, ⌘/Ctrl-wheel zooms at the pointer, − 100% + Fit, dot grid, legend, status line). **Select** clicks a box or an arrow's label and drags boxes; **Draw link** (L) shows four ports per box and links port to port into a *New link — not saved yet* panel. Line style follows Q2 (dashed cloud · solid direct · double gateway), arrowheads follow Q1; arrows are neutral until selected. Undo/Redo (⌘Z/⇧⌘Z), Delete key, protocol-for-new-links dropdown (all 12), How to draw dialog, *Clear and draw myself*. The link panel asks the three questions as radio pills and shows **Filled in for you** (source/target role, topology, cloud type, sensor field); **Delete this link** lives there, not in the toolbar (D3). A step cannot be left with an unsaved link on it.
- **Review fills in every field from the map** (`product-form.tsx`, `derive.ts`) — network settings (name, cloud collection, password with an accessible show/hide, cloud type, network type, frequency filtered by protocol) and **All parameters** (the five Figma reference tables, read from the same catalog the controls use); a row per product (role chip + *Ready* / *Needs sensor type*) with Topology, Master, Interfaces (add/remove), Add repeater (hidden for CAN/RS-232/I2C/SPI), Sensor type (17), Agent placement, Shares data with cloud (off while Sensor = None or no agent), Bridge (read-only, on at 2+ interfaces), Redundancy (Standby for a product with no links). A field the maker changes stops following the map (`touched`). Roles come from the arrows (Figma Role rules). **Create network** names the first thing missing (a cloud password when cloud type ≠ None; a sensor type when a link says *Sensor data*); a product whose parts name no radio for its interface gets a warning. Choosing a new Master that breaks links opens *Changing Master will remove N links* with the computed list (D7).
- **The Connection Map page** (`connection-map-page.tsx`, Figma 11–17) — breadcrumb, name, *products · links · shared cloud · last edited <date>* (no person's name — D8), the read-only map with a Network summary; a box shows its sentence and Product settings, an arrow its answers read-only (D5). **Edit map** runs the same editor on a draft, with *N unsaved changes* listing what changed (links added/removed/changed, Master changed to X, product settings, boxes moved), Cancel (confirms when there are changes) and Save changes. **Settings** (`network-settings-dialog.tsx`) edits the whole-network fields and carries **Delete network** (D9) behind *Delete "<name>"?*.
- **The project page's Network section** (`network-section.tsx`, Figma 01 / 10) — *No network yet* with **Create Network** (the one home — no kebab menu, D10), or the network's summary, connections and products with role chips, and **View Network**.
- **Persistence** (`store.ts`) — one network per project (D12) in `localStorage` under `ideeza:network:<projectId>`, shape-checked on read (`sanitizeNetwork`) and read through one `useSyncExternalStore` hook, so the review card, the project page and the map agree without a reload.

## Projects, history & community
### My projects
- **My projects** (`projects/my-projects.tsx`, `lib/manual/project-list.ts`): status is the Brief's own outcome (Draft · Private · Given · **Listed** · **Sold** · Minted); tabs **All · Draft · Private · Given · Listed · Sold**, then **Showcase** as a membership tab (a project's `showcasedAt` flag, not a status); search, a Source facet, sort, 12-per-page pagination. Listed holds live and paused listings; Sold holds a project with a Main sale and no live listing; "Minted" (unreadable record) shows under All only.
- **Cards are market-aware** (`project-card.tsx`): each reads the live market stores, and its one button is the header pair's violet step (`ActionPair.card`: Review version *n* · Continue Brief · Add Brief · Add to marketplace, which opens `/projects/<id>?list=1`), never a "View …".

### Project page (`/projects/[id]`)
- **Shell** (`projects/details/*`, sections plug in through `SLOTS` in `project-page.tsx`) reads one derivation, `projectView()`, for everything below. The status chip, the Showcase badge, the *Utility NFT* pill, the lock line and the role chip of a contributor preview sit in the header; there is no "Open in editor" here (it lives on the product page). A rebuilt chat becomes the same project's next **version**; a product a rebuild drops stays listed, marked "Not in version n · from version m".
- **Header action pair** (`nextAction()`): one violet step per state (Add Brief · Continue Brief · Review version · **Add to marketplace** · **Close auction** and **Relist** in the rail), then View brief, then *Preview as buyer* (quiet). "Listed" now means live on Explore marketplace; the old "goes on sale when the marketplace opens" line is gone.
- **Tabs:** Products · Media (videos first, then images) · Network · **Contributors** (the owner's roster: name, role, ownership %; add/edit dialog; a read-only credit in a buyer preview) · **Customers** (real Main and edition sales, an empty state until the first sale; owner only).
- **Rail** (`RAIL_ORDER`): **Marketplace** (the listing's one home: Edit · Remove · View on marketplace · Bidding History · Close auction · Relist; Main / Physical / Virtual summary tabs) · **Outcome** (mint proof, payout wallet change, Showcase row) · Details · **Legal** (Patent · Copyright · Trademark as typed, never verified) · Versions · **Project log** (created, minted, listed, sold, showcased, support requests) · Manage (Delete, blocked with its reason while Listed, Sold or another owner holds a share). Below 1024 px the Marketplace block moves above the tabs.
- **Preview as buyer** (`?view=buyer`) and **Preview as a contributor** (`?view=contributor&as=<id>`): the read-only pages those viewers see; a buyer sees previews only, no firmware, no downloads.
- **Showcase** is a flag with a readiness gate: every current product needs a ready video, the same rule as Sell, Give, Relist and an edition. It is honest that nothing posts anywhere while Innovations is a sample feed.
- **Edit gate and lock** (`edit-gate.ts`): editing a live Buy-now project asks to pause the listing; a running or ended-unclosed auction blocks edits; **after a 100 % sale the project locks** (name, description, products and listing read-only, delete blocked).
- **Activity** (`details/activity/*`, `lib/manual/journey*.ts`): the header chip opens a drawer of newest-first entries (11 stages plus Others, description, https links, media saved to IndexedDB, price snapshot); Add / Edit / Delete are owner only. The product page's chip is scoped to that product.
- **Business plan** (`projects/business-plan/*`, `lib/manual/business-plan*.ts`): the header chip runs a seven-section plan section by section through `/api/business-plan/section` (keyless text model; a section either is written or shows "Couldn't write {Section}", never filler). The runner is mounted at the app layout so a run continues across pages; a section the model answers busy (429/503) is asked once more after about 5 s, and Try again is offered only once no run is live. `/projects/<id>/business-plan` reads it, edits it (page-wide edit mode; Improve sends the section's own text) and keeps capped versions with Regenerate, in a portalled **Version *n* ▾** popover (View · Restore). Sold in full, the plan page is read-only: the lock line shows and Edit, Regenerate, Restore, Try again and Delete are off.
- **Save flow** (`create/save-step.tsx`, `lib/manual/save-step.ts`, `details/saved-banner.tsx`): the build review asks for the name and details (shared description fields, *Update with AI*) before Save; a rebuild of the same chat offers version mode; Save lands on `/projects/<id>?saved=<buildId>` with a one-shot arrival banner; **Add a product** returns Home with `?addTo=<projectId>`.

### Product page (`/projects/[id]/products/[productId]`)
- **Header:** breadcrumb, product name, Activity chip (scoped), build check and version select, and the page's one violet **Open in editor** (or *Open in editor · {Step}*), absent when the project is locked. There is no sample-board hint. Version history (the select, the version notices, other versions' images) is the owner's: a buyer sees the version on offer only.
- **Tabs:** **Media** (default; the video player, Regenerate, Takes, then the product's images) · 3D model · PCB · Firmware code · Wiring · Parts, then **Contributors** (read-only credit) and **Customers** (this product's edition sales). A piece the build never made has no tab; a hand-made product has Media · Contributors · Customers only. A demo buyer without a holding sees no Firmware tab; a holder gets it and the downloads.
- **Rail:** **Marketplace** (this product's Physical NFT and Virtual NFT editions, see Editions) and **Editor** (six rows into the product's editor, the seed caption "Opens with version *n*'s …", and the one home of **Load version *m*…** and **Restore version *b***, see BUILDLOAD).
- **Per-product editor:** progress facts come from that product's own documents (`lib/manual/editor-work.ts`); the route and store are in [editor-modules.md](editor-modules.md).

### Video
- **A real browser-made clip** (`video-jobs/clip-renderer.ts`, `lib/video/*`): each product keeps takes (`ProductVideo`), at most one in use. The render draws a 10 s, 30 fps, silent file from the product's image and three on-screen lines and encodes it in the browser (WebCodecs MP4, MediaRecorder WebM fallback); the honesty line says the AI video model is not connected yet. Files live in IndexedDB; the player, Generate dialog, lightbox and global render indicator read the same job.
- **Readiness gate** (`lib/manual/readiness.ts`, `details/readiness-dialog.tsx`): a rendering video is not yet a video. One rule set gates Showcase, Sell, Give, Relist and a single edition, and the dialog lists what is missing per product.

### Mint
- **Lazy or Instant** (`wallet/mint-type-field.tsx`, `lib/wallet/mint.ts`): one shared field in the Brief form and the listing form. Lazy is a free signature and mints on the first sale; Instant pays the network fee now. The Outcome block shows the mint proof (token, signature or transaction, payout wallet).
- **Demo wallet** (`components/wallet/*`, `lib/wallet/*`, key `ideeza:wallet:demo`): six local identities (the maker's three accounts and Explore's three demo buyers) with seed balances derived, never stored, in exact bigint micros. Every signature and transaction opens one Demo wallet dialog (connect, address, balance, charge estimate, confirm); the account menu's *Wallet & tokens* entry manages identities. Nothing touches a chain and every record is labelled *Testnet demo*.

### Marketplace
- **Listing** (`projects/listing/*`, `lib/market/listing*.ts`): the *Add To Main NFT Marketplace* form (Buy now or Auction, price, royalties, share, benefits) lists a project for real; Edit, Remove, Pause and Relist, Bidding History and Close auction (winner is the highest bid whose demo wallet still covers it) run in the rail block. The Brief's Sell step renders the same fields and writes the same listing, in the order MintRecord → listing → the draft's `mintedAt`, so a refused listing write leaves nothing minted.
- **Explore marketplace** (`/marketplace`, `components/marketplace/*`): For sale · Sold · Purchased tabs, search, Type and Sort, with a *Shopping as* switch (Mira · Leo · Sam). `/marketplace/[id]` is the project page as a buyer sees it (a paused listing reads *This project is off the marketplace for now* instead, unless the active buyer already holds part of it), with the buyer rail: Buy now card, Auction bid card, Purchased Summary and **Get creator support** for a holder (recorded as a support request that shows in the owner's log), and edition offers.
- **Buying and bidding** (`lib/market/purchase.ts`, `auction.ts`): a demo purchase or bid confirms through the wallet dialog and writes an append-only sale or bid; a Main share is never oversold; sales become Customers and holdings. **IDEEZA takes a 2.5 % fee** on every sale, paid by the seller out of the price (`IDEEZA_FEE_BPS` in `lib/market/fee.ts`).

### Editions
- **Physical and Virtual NFT editions** (`projects/editions/*`, `lib/market/editions*.ts`): on the product page a track is a lazy-minted batch per kind and use (create, list, edit, add NFTs), gated by the Main listing being live or paused and by the product's video readiness; buyers choose Regular or Extended. The project page shows a read-only summary per product.

### BUILDLOAD
- **The editor opens a product with its own build** (`lib/manual/build-load*.ts`, `lib/pcb/from-build.ts`, `lib/three/from-build.ts`): the first open seeds that product's board (schematic from the build's parts and nets, then the editor's own Convert), 3D scene, firmware file and wiring parts, never over the maker's work; a refused write leaves nothing behind. **Load version *m*…** replaces a document only through a confirm, keeps a one-slot backup, and **Restore version *b*** brings it back; an import notice explains what came in and can be dismissed.


### History, Innovations, minting
- **History** (`create/history-*`): Model Generations · Project/Product Generations.
- **Innovations** community feed (`components/newsfeed`): Discover/Following, category filters, project cards with **minted badge**, empty states; Explore marketplace.
- **On-chain minting** via the Brief module (idea → video → **mint** → success); "no wallet/KYC to start, only when you sell".

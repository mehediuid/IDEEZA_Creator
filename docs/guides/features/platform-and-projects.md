# Features — platform, projects & network

Part of the feature inventory ([index](README.md)). Moved verbatim from `CLAUDE.md` §5 on 2026-09-29. Keep it current: [AGENTS.md › Keeping docs current](../../../AGENTS.md#keeping-docs-current-required).

## Platform & shell
- Global sidebar nav (Home · History · My projects · Parts & agile module · Explore marketplace · Innovations · Messages · Blog); top bar with search, profile dropdown, plan badge, Tutorial / Tour guide / Help / Report. **At phone width the sidebar is a drawer** (`sidebar.tsx` `MobileBar` + `SidebarDrawer`): below `md` a 56 px bar carries the menu, the mark and search, and the menu opens the same sidebar body over the page with a backdrop, Escape, focus held inside and handed back on close, closing itself on arrival at a new page (it remembers the page it was opened on, so no effect is needed). It used to stay open at 280 px beside every page, leaving the page 120 px — the home headline broke a word a line and the chat's canvas was off the screen (verified at 400 px: every page is 400 wide with nothing past the edge).
- **⌘K command palette** (`dashboard/command-palette`); light/dark theme (`theme-provider` + toggle).
- **`/parts` — Parts & Agile Module** (`app/(dashboard)/parts` + `components/parts/parts-library.tsx`, from the `feat/parts-agile-module` branch): the part catalogue, the captured Agile Modules and the packages the maker has authored, on one section rail over a dense list — the real flow for this destination. `/parts/new` is the New Package authoring wizard and `/parts/<id>` one part with its land pattern. *(An earlier branch put a per-build bill-of-materials index on this route; it was removed on the merge rather than left as a second parts destination — a build's BOM lives where it is produced, on the build's own Parts tab at `/build/<id>?tab=parts`, which the project page links as **Bill of materials**.)*

## Add Network & Connection Map (`lib/network`, `components/network`, Figma `HDtWAU2PSbjQKlEWgHI3ev` · `44533:123190`)
Built to the spec `docs/superpowers/specs/2026-09-24-add-network-design.md` (decisions D1–D12): Figma supplies the requirements, the app supplies the look.
- **The Add Network wizard** (`add-network-dialog.tsx`) — one dialog, five steps (Setup · Method · Connect · Review · Done) with a stepper, Back on every step and a *Discard this network?* confirm once there is progress. **Setup**: the four goals (Control all via 1 App · Products talk to each other · Both — app + direct · Cloud-only data sync) and the project's products as cards with a chip derived from the build's parts (`ESP32-S3 · Wi-Fi + BLE` — MCU plus the radios the part names imply; *No parts listed* when there are none), *N selected · M not included*, and a gate (≥1 product, ≥2 for the two local goals). **Method**: AI Auto-Map or Manual Canvas and the three-questions note. **Done**: *Network created*, a line that says *saved* (never *live* — D4), the 09b variant when no Cloud Name was entered, product → role, **Close · View Network** (D2, busy *Opening…*).
- **AI Auto-Map is a real model call with an honest fallback** (`api/network/automap` + `planner.ts`) — the products (names, descriptions, parts) and the goal go to the keyless Pollinations `openai-fast` model on its OpenAI-shaped endpoint with low reasoning effort (≈12 s for four products, under 30 s for six; the plain endpoint took 30 s and wrapped the answer in its reasoning), 45 s timeout. Every proposed link is validated against the boxes on the map and the three questions' own values and dropped, never repaired (`validateAiLinks`); a hub product the AI routes others through is moved to the middle column (`arrangeFor`). No valid link → the **rule planner** (the Figma Role-rules table read backwards: sense + act → two-way, sense → reports, act → is told) draws it and the banner says so. The proposal is reviewed as a list with the roles it produces before the canvas opens (Figma 04).
- **The connection canvas** (`map-canvas.tsx` + `map-editor.tsx`) — HTML boxes (product · MQTT Broker *C* · App *A*) and SVG arrows on one pan/zoom plane (wheel pans, ⌘/Ctrl-wheel zooms at the pointer, − 100% + Fit, dot grid, legend, status line). **Select** clicks a box or an arrow's label and drags boxes; **Draw link** (L) shows four ports per box and links port to port into a *New link — not saved yet* panel. Line style follows Q2 (dashed cloud · solid direct · double gateway), arrowheads follow Q1; arrows are neutral until selected. Undo/Redo (⌘Z/⇧⌘Z), Delete key, protocol-for-new-links dropdown (all 12), How to draw dialog, *Clear and draw myself*. The link panel asks the three questions as radio pills and shows **Filled in for you** (source/target role, topology, cloud type, sensor field); **Delete this link** lives there, not in the toolbar (D3). A step cannot be left with an unsaved link on it.
- **Review fills in every field from the map** (`product-form.tsx`, `derive.ts`) — network settings (name, cloud collection, password with an accessible show/hide, cloud type, network type, frequency filtered by protocol) and **All parameters** (the five Figma reference tables, read from the same catalog the controls use); a row per product (role chip + *Ready* / *Needs sensor type*) with Topology, Master, Interfaces (add/remove), Add repeater (hidden for CAN/RS-232/I2C/SPI), Sensor type (17), Agent placement, Shares data with cloud (off while Sensor = None or no agent), Bridge (read-only, on at 2+ interfaces), Redundancy (Standby for a product with no links). A field the maker changes stops following the map (`touched`). Roles come from the arrows (Figma Role rules). **Create network** names the first thing missing (a cloud password when cloud type ≠ None; a sensor type when a link says *Sensor data*); a product whose parts name no radio for its interface gets a warning. Choosing a new Master that breaks links opens *Changing Master will remove N links* with the computed list (D7).
- **The Connection Map page** (`connection-map-page.tsx`, Figma 11–17) — breadcrumb, name, *products · links · shared cloud · last edited <date>* (no person's name — D8), the read-only map with a Network summary; a box shows its sentence and Product settings, an arrow its answers read-only (D5). **Edit map** runs the same editor on a draft, with *N unsaved changes* listing what changed (links added/removed/changed, Master changed to X, product settings, boxes moved), Cancel (confirms when there are changes) and Save changes. **Settings** (`network-settings-dialog.tsx`) edits the whole-network fields and carries **Delete network** (D9) behind *Delete "<name>"?*.
- **The project page's Network section** (`network-section.tsx`, Figma 01 / 10) — *No network yet* with **Create Network** (the one home — no kebab menu, D10), or the network's summary, connections and products with role chips, and **View Network**.
- **Persistence** (`store.ts`) — one network per project (D12) in `localStorage` under `ideeza:network:<projectId>`, shape-checked on read (`sanitizeNetwork`) and read through one `useSyncExternalStore` hook, so the review card, the project page and the map agree without a reload.

## Projects, history & community
- **My projects and Project details** (`projects/my-projects`, `projects/details/*` — a shell whose sections plug in through `SLOTS` in `project-page.tsx` — and the new `projects/[id]/products/[productId]` product page) — the status is the Brief's own outcome (Draft · Private · Given · **Listed** · Minted; `project-summary.ts`); tabs **All · Draft · Private · Given · Listed**, then **Showcase** as a membership tab, not a status (a project's own `showcasedAt` flag, `project-read.ts`); search, a Source facet, sort and 12-per-page pagination — the old **Public · Contributed · Utility NFT** filters are gone (no auth yet, and nothing here is a real benefit NFT). Project details reads one shared derivation (`projectView()`) for its header (inline rename/description, one action pair from `nextAction()`), **Products · Media · Network** tabs and its rail (**Outcome · Editor · Details · Versions · Project log · Manage**). A rebuilt chat becomes the same project's next **version** (not a same-named twin); a product a rebuild drops stays listed, marked "Not in version n · from version m", and its page opens at the version it was last in. **Showcase** (`setShowcase`) is a flag, not a Brief outcome — a badge beside the status chip and its own My-projects tab, honest that nothing posts anywhere while Innovations is a mock feed. **Preview as buyer** shows the read-only page a buyer would see: 3D, PCB, wiring and parts previews only, no firmware source, no downloads.
- **History** (`create/history-*`): Model Generations · Project/Product Generations.
- **Innovations** community feed (`components/newsfeed`): Discover/Following, category filters, project cards with **minted badge**, empty states; Explore marketplace.
- **On-chain minting** via the Brief module (idea → video → **mint** → success); "no wallet/KYC to start, only when you sell".

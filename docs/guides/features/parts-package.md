# Features — Parts & the New Package flow

Part of the feature inventory ([index](README.md)). Moved verbatim from `CLAUDE.md` §5 on 2026-09-29. Keep it current: [AGENTS.md › Keeping docs current](../../../AGENTS.md#keeping-docs-current-required).

## Part authoring — New Package flow (`/parts/new`, `components/package`, `lib/package`)
- **`/parts` is the home, and it is built for finding** (the sidebar's Parts & Agile Module destination, which used to 404): a **section rail** on the left — All parts · one row per symbol kind present (Resistors · Capacitors · … · Connectors, derived from the data so an empty kind never shows) · Agile Modules · My packages, each with a live count that follows the search — and a **dense list** on the right, one 52px row per thing: a 40px symbol thumbnail, the MPN, one line of the facts that tell rows apart (`0402 · Yageo · Resistor, 1%`), and one mono fact on the right edge (price · part count · version). The whole catalogue fits one screen, so there is no pagination. It used to be a grid of large 16:10 cards each dominated by a symbol drawing — and every resistor draws the same symbol, so the picture said nothing while the distinguishing facts sat in small type underneath, and fifteen parts took two screens. A **grid view is one toggle away** (remembered per browser under `ideeza:parts:view`, read through `useSyncExternalStore` so hydration agrees), compact cards with no badges: the rail already says what you are looking at. Authored packages are listed from the library itself, not from `allParts()` (which folds them into catalogue rows for the PCB picker), so nothing appears twice. Below `lg` the rail becomes a scrolling chip strip.
- **`/parts/[id]` is the depth behind a card** — a **Package** shows its real symbol *and* footprint side by side plus every field the library stores (category · pins · pads · mounting · reference · value · body height/standoff/rotation · how it was authored · version · created); an **Agile Module** lists the parts it is built from, each linking on to its own page; a **Part** shows its symbol, manufacturer, package, price, stock and land pattern. Nothing is invented — where the model has no answer the page says so, and a part whose land pattern disagrees with its package says exactly that (`placing it gives a SOIC-8 pattern, not a SMD-53 one`), because `FOOTPRINT` is keyed by symbol *kind*, so every IC in the catalogue converts to the same SOIC-8. **Place on a board** greys out with a reason when no project is open, rather than going nowhere. The library lives in localStorage, so an id only resolves in the browser that holds it — the not-found state says that too.
- **A part's land pattern comes from its package, not its symbol kind** (`lib/pcb/land-patterns.ts`) — `landPatternFor("QFN-56")` returns real pad geometry, generated by the **New Package wizard's own `padsFor`**, so a catalogue part and a hand-authored one are described by one generator rather than two that drift. It parses the families whose names really do determine geometry: chip codes (0201…2512), SOD/SMA/SMB/SMC, SOIC/SOP/SSOP/TSSOP/MSOP, SOT/TSOT, DIP and QFN/QFP/TQFP/LQFP — **12 of the 15 catalogue rows**. The other three (`SMD-53`, `USB-C-16P`, `TH-5P`) name a vendor outline, not a standard body, so they resolve to `null` and the page prints *why* instead of drawing an invented pattern. Nominal reference geometry, not IPC-7351. Two traps it was written around: the trailing number is a pin count in `SOT-23-6` but a body code in `SOT-23` (which briefly produced a 23-pad part), and `padsFor`'s quad `span` is centre-to-row, so passing a width made a QFN-56 twice its real size. **The board's converter still picks by kind** — `FOOTPRINT`'s four land-pattern glyphs are baked into the BOM sets, delete categories, 3D scene and exporters as object *kinds*, so moving it onto this geometry is its own change; until then the part page says outright that placing gives a different pattern from the one drawn.
- **Five steps + confirmation**, one `PackageDraft` (`lib/package/types.ts`) behind all of them, debounce-persisted to `ideeza:package:draft` so a reload mid-authoring loses nothing. **The step you were on comes back with it** (`ideeza:package:step`, clamped on load to the furthest step this draft really opens): the part used to survive a reload while the place in the flow did not, so the logo menu's own promise that "leaving here and coming back picks up where you left off" reopened on step 1. Filing the package clears both. One `blockedReason()` drives the Next button, the rail's reachability *and* the banners, so the three can never disagree; an unreachable rail step names the gate holding it.
- **Snap wears the snap glyph** — both package editors drew their Snap toggle with `tAlignGrid`, which everywhere else in the app means *Align to Grid / Tidy up*, a one-shot action that moves a selection onto the grid. The app's own `snap` magnet was sitting unused a row away.
- **Neither package editor carries a Select row** (UIUX-7/11, like the PCB and schematic palettes) — selecting is what the pointer does when nothing is armed, so a button for it can only be redundant. `"select"` is still the model's name for that resting state; it has no button. **Esc comes back to it from the toolbar as well as the canvas** — the canvas always handled Esc, but focus sits on the tool button right after you arm something, so without the row a keyboard user had no way back until they clicked the canvas first. Both resting hints say so.
- **Brand violet marks what is chosen, not what is on screen** — all three starting-path cards painted their icon violet whether chosen or not, a family card tinted its title violet on hover (the card's own border and lift already answer a hover), and a computed text object — a Designator or a Value — was painted violet on both canvases, which is the *selection* colour's hue there, so it read as permanently selected. Computed text keeps its semibold weight as the marker and gives up the colour.
- **A pin number is an identity, so it commits on blur or Enter** (`PinNumberField`, step-symbol.tsx) — it used to write through on every keystroke, so typing `12` over pin 3 committed `1` first; if pin 1 existed the store refused it and the field snapped back, which meant the numbers you could reach depended on the numbers already taken. `parseInt` also read `3x` as 3. The store's own `renumberPin` refuses a non-integer or a number below 1 by name rather than coercing it — `Math.max(1, Math.round(n))` turned 0 into pin 1 silently and passed `NaN` straight through into the pin and every pad pointing at it.
- **A `Field` names whatever it wraps** (`Field` + `FieldSelect`, editor-chrome.tsx) — `<label for>` only reaches a labelable element, and a `Select` renders a `<button role="combobox">`, so every Select in this flow was announced as an unnamed combobox with a perfectly good label sitting above it; the category field's `htmlFor` pointed at an id nothing carried. The Field gives its label an id and provides it through a context that `FieldSelect` reads, so the association cannot be forgotten at a new call site; a Select in a table cell names its own row instead (`Pad 3 shape`, `Pin 2 electrical type`), the way the number fields beside it already did. `ToolbarSelect` carries an explicit `aria-label` — it used to wrap the control in a `<label>`, which named nothing. Verified: 28 comboboxes across Symbol, Footprint and Finalize, 0 unnamed.
- **A field is as wide as what goes in it** (`FIELD_WIDTH` in editor-chrome.tsx: `num` 150 · `short` 260 · `full`) — the forms were sizing every control by the grid it sat in, so a single-letter reference prefix got a 660px box and `1.2` a 715px one, which is what made the flow read as unfinished. The width caps the control alone; the hint keeps its own measure, or a one-line hint under a 260px Select breaks in two. The wizard's parameters now sit in **the same card as the preview they drive**, with the unit picker in the card header and the numbers in a `max-content` grid so a short list reads as a row rather than a stack.
- **A family card draws the arrangement it generates** — the picker was 24 text-only tiles on a page whose whole subject is geometry; each one previews the real pads from the same `padsFor` that builds the footprint, so a two-pad, a grid and a quad are told apart at a glance rather than read.
- **A breadcrumb says where you are inside step 1, and gets you back out** (`Breadcrumb`, editor-chrome.tsx) — the wizard and import paths are three screens deep, and the only way back was the footer's Back button in the far bottom-left corner, a long way from the eye and silent about where you were. Each sub-screen now opens with `New Package / Part Wizard / Diodes`; every crumb before the last is a real control that returns to that screen (and can skip a level — from the parameters straight out to the paths), the last is the screen you are on, so it is text rather than a link. The footer's Back is unchanged: it is the flow's one consistent step control.
- **The logo is the door out** (`LogoMenu`, flow-shell.tsx) — the flow covers the whole viewport, and the mark in its top-left was `decorative` with no handler, so the only exit was the X in the opposite corner, which went to one place without saying where. Clicking the mark now opens a menu naming every destination — **Home · Parts & Agile Module · My projects** — each with a line saying what it is, over a note that the draft is kept. A real menu, not a painted one: the trigger is a button announcing `aria-haspopup`, the panel is a `menu` of `menuitem`s, **focus moves into the rows** so ArrowDown/Up walk the destinations and Enter opens the one under the highlight, Home/End jump to the ends, Escape closes and hands focus back to the trigger, Tab closes on the way out. The arrows used to move a highlight and nothing else — the key handler sat on the trigger, which kept focus, so Enter re-toggled the menu instead of following the highlighted row, and no destination could be reached from the keyboard at all. The note is true and tested: leaving from the Diodes parameters and returning lands back on the Diodes parameters.
- **Three ways in**, all converging on the same spine (`entrySub()` derives the sub-screen from the draft, so a reload lands where you were and Back walks out by clearing what got you in):
  - **Custom** — a blank canvas.
  - **Part Wizard** — **24 families across 8 arrangements** (`lib/package/wizard.ts`); picking one pre-fills its prefix, mount and parameter set, the preview **redraws on every keystroke**, and Next generates the symbol *and* the footprint from the same generator the preview draws (so the picture cannot promise different geometry). Dual-row and quad number counter-clockwise from pin 1, the way a datasheet does. *Nominal reference geometry, not IPC-7351 toe/heel/side — stated in the UI.*
  - **Import** — three discrete files (`.kicad_sym` · `.kicad_mod` · `.step`), each parsed for one purpose (`lib/package/kicad.ts`, one S-expression reader for both KiCad formats). Pulls the reference prefix, value, pins with their electrical types, pads with real mm geometry, silkscreen lines/circles/rects/polys, and maps `np_thru_hole` to a **Mounting** pad. The result screen shows a match/mismatch banner, side-by-side previews of what actually landed in the draft, and an honest list of what the files carried that this flow does not model. A `.step` is verified by its ISO-10303-21 header and its solid count is reported — tessellating it needs a CAD kernel, so the 3D step still places a box.
- **Symbol Creator** — direct-manipulation SVG canvas: 10 tools (Select · Pin · Line · Polyline · Rectangle · Circle · Ellipse · Arc · Bezier · Text), press-drag / two-click / multi-click drafting with Enter · double-click · first-vertex close and Esc cancel, per-kind resize handles, grid 5/10/20/40 + Snap, and the pin table (`#` · Name · Electrical type (9) · Length · rotate · delete, + Add pin / + Add 4 pins). **Renumbering a pin carries its pad with it**, so the match can't silently break. Tool list is cross-checked against the live schematic Insert toolbar, with the two departures the spec names: Pin added, Power left out. It borrows the schematic's own `--color-canvas-*` state vocabulary and its transparent fat hit band under `pointer-events:none` ink, so a line is pickable without a pixel hunt.
- **Footprint Creator** — real millimetres with the part's centre at the origin, 0.5 mm grid, 10 tools (Add Pad with an inline **Pad kind** sub-selector · Line · Polyline · Rect · Circle · Ellipse · Arc · Dimension · Text) on the four real layer names (Top/Bottom Silkscreen · Top/Bottom Paste Mask). The **model is always mm** and mm/mil is display only, so the toggle **reformats every field and table column** without rounding the geometry. Inline-editable pad table (Pad · Pin · Kind · Shape · W · H · Drill (THT only) · X · Y · delete); the **pin/pad banner** is the gate — a **Mounting** pad is mechanical and excluded from the count on purpose, and converting a pad to Mounting gives its pin back *and* makes it a real hole.
- **3D Placement** — a real three.js viewer (dynamic-imported `ssr:false`, the PCB 3D tab's own pattern), drawing the board, the **real pad layout as reference patches** and the body against them, with X/Y offset, standoff Z, rotation, body height and body colour driving it live. Scene colours are read from the design tokens and re-read on a theme flip. Body width/depth come from the silkscreen outline when one was drawn, else the pad extent.
- **Finalize + confirmation, saying where the package really goes** — name and category are both required before the action enables, and the action is **Save**, because saving is the only thing that can happen: there is no backend, so a package lives in this browser's `localStorage`. *Publish to community* is therefore **greyed with the reason** rather than offered, and the confirmation no longer promises publishing "later" from a screen that carries no such control. **Versioning is real and unconditional** — the store is append-only by (name, version), so a re-save under an existing name files v2 and leaves v1 where it is; the aside says which version is about to be filed and the confirmation names the one that was. The copy used to tie versioning to publishing, which is not how the store ever worked. The confirmation reports Pins · Mount · Path · Visibility, and *Create another package* restarts the flow.
- **The result is a real part**: written to `ideeza:pcb:personalPackages` and surfaced as a catalogue row through `part-catalog.ts`, so the Place-a-Part picker's **Personal** rail, its filters and its search all find it. *(It places a generic `component` glyph for now — drawing stored symbol geometry needs `placed-objects.tsx`.)*
- **What the flow added to the design system**, because it needed it and the DS did not have it: `TextInput` + `Textarea` (with an in-field unit `suffix`), `Slider`, `Banner` (two tones, no neutral third), `Segmented`; the **`--line-height-*` and `--letter-spacing-*` scales**, which were missing entirely (Figma defines them, `tokens.css` did not — hence arbitrary `leading-[19px]` at every call site); `--color-pad-copper` / `--color-pad-mechanical`; five purpose-drawn step glyphs in the icon dictionary (`pkgPackage` … `pkgFinalize`) plus `pPin` / `pLine`; and `componentBodyColor` lifted into `pcb-3d.ts` so the PCB 3D scene and this flow paint a body from one source.
- **The flow holds the keyboard while it is open** — it is a full-viewport overlay, so everything it covers is marked `inert` on mount and released on unmount (`useInertBehind`, flow-shell.tsx). Without it Tab walked the dashboard sidebar *behind* the overlay: measured 16 stops on controls the user cannot see, and the flow's own controls were never reached. Now measured 0 of 18 stops behind it, starting at the flow's own Close button. The **two editor steps take the width they are given** (1400px vs the 1000px prose cap the other steps read at), so the 10-column pad table fits without scrolling from 1440 up; below that it scrolls inside its own container and the page body never does.
- **PCB `Project ▸ New ▸ Part…`** now opens this flow instead of the old five-field form, which wrote a shallow catalogue row and said outright that the symbol editor "isn't built yet". Its interstitial lists the steps from the flow's own `STEPS`, so the count in the sentence and the rows under it come from where the rail and the "Step N of 5" readout come from — written out by hand it said "four steps" and listed four, having dropped the step that picks how you start.

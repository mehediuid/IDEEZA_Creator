# Features — PCB module: schematic editor, connectivity & ERC

Part of the feature inventory ([index](README.md)). Moved verbatim from `CLAUDE.md` §5 on 2026-09-29. Keep it current: [AGENTS.md › Keeping docs current](../../../AGENTS.md#keeping-docs-current-required).

## PCB module — schematic editor
- **One canvas state vocabulary, from tokens** (`tokens.css` "Canvas interaction states" → `placed-objects.tsx`): **hover emphasises the object, not a box around it** (UIUX-25) — every glyph paints in `currentColor`, so hovering takes the `--color-canvas-hover` accent into the symbol itself and thickens its strokes to 2.6 (`.ix-hot`), which reads as the part's own linework, pin numbers and label going bolder; a note's letterforms bolden instead, and an image — which has no strokes — brightens its own frame. It used to draw a plain rounded rectangle around whatever was under the cursor, which is what the ticket objected to. Suppressed while a place/draft tool is armed, because the click then belongs to the tool. **selected** = 1px dashed `--color-canvas-select` + `--color-canvas-select-fill` — a *marker*, so it can never be confused with hover's emphasis; verified across **all 21 schematic entities** (UIUX-26: wire · bus · line · arc · ellipse · bezier · rectangle · polygon · junction · no-connect · power · ground · net label · net flag · port · text · table · image · component · pin · agile module) that each one changes on hover, never boxes, carries a selected state, and that the two differ. Fixed on the way: the **text** object never received the hover handlers at all, and the **image** drew the same dashed frame for hover and selection.
- **Drawing primitives have a standard colour on the sheet too** (UIUX-17, `SCHEM_DRAW_COLOR` + `--color-schem-draw-*`) — the board's `--color-draw-*` are picked to sit on dark green substrate, and the sheet was borrowing them, so a `gray-300` line all but vanished on white paper. The sheet carries its own set with the same meanings — a plain rule · a closed shape · a curve · a note — so the six primitives the ticket names (Line · Circle/Ellipse · Arc · Rectangle · Polygon · Bezier) take four colours rather than six unrelated ones, defined for **both themes** (verified: `#475569` on the white sheet, `#cbd5e1` on the dark one). A colour set on the object still wins. Fixed on the way: `PlacedGlyph` kept its *own* `DRAW_COLOR` lookup and so painted board colours on the sheet whatever the mode — the standard colour is resolved by the parent, which knows the mode, and passed down. **net highlight** = amber (`--color-canvas-highlight`), a different hue on purpose since it marks a net, not a pick; rubber band + lasso share `--color-canvas-marquee-fill`. A wire can't carry an outline, so it speaks the same colours instead (stroke swaps, 1.7 → 2.6px, plus a glow of the select token). Every state colour used to be a hardcoded `rgba(124,45,185,…)` per call-site, so it couldn't differ per theme and drifted between kinds. **Wires are pickable, not a pixel hunt** — the visible ink stays 1.7px (`pointer-events: none`) over a transparent 9px hit band that carries the id, hover and click. Object tooltips read `R1 · resistorBox` (name + kind). The states are captured from the running editor in both themes in the canvas-states sheet artifact.
- **An armed tool says so in three places** (`tool-labels.ts` + `canvas-area.tsx`): the palette button lights up, the **hint chip** over the canvas names the tool and the next click (`GND · Click on the sheet to place · Esc cancels`; draft tools read `Click to start, click again to finish`), and one-click placers show a **ghost of the symbol** at the position it will actually land on — snapping included — drawn from `glyphFor()`, the same geometry the placed object uses, so the preview can't drift. Names come from the palette's own option labels (`buildToolLabels`), with a prettifier for menu-only tools, and a rail variant says what it will stamp (`DGND (GND)`); the status bar shows that label instead of the raw id it used to print (`vcc5v`, `netBusLabel`). The ghost, like the crosshair, is moved by direct DOM writes inside `requestAnimationFrame`.
- **Sheet templates are real** (`schem-properties.tsx`) — the Template dropdown is *derived* from (paper size + orientation): picking `A3 Portrait` sets both and the sheet redraws, changing either directly reads back as `Custom`. It used to write `schemBasic.template`, which nothing read. **The on-canvas title block is labelled** (UIUX-68) — it printed an unlabelled strip (`Ayaan K. · Rev C 1/2 SB-001 A4 Landscape 2026-07-16`), so a reader had to know the schema to tell a doc number from a date. Now the sheet title is the heading and everything else is a **label / value grid** (Company · Project · Author · Doc No. · Revision · Sheet · Date · Size), each row appearing only when that field is set. **Project falls back to the project actually open** (`state.activeProjectId` + `recentProjects`), so the row names it instead of vanishing when nobody typed one, and the header is always the IDEEZA mark — it used to print the company *or* "IDEEZA" as a fallback, so an unset company read as our branding. `Sheet ▸ Name` now renames the **active sheet** (the name the Sheets tree and page tabs show) instead of a dead field, and the title block gained the two fields the brief named: **Project** (in the subtitle line) and **Sheet size** (read-only — it *is* the border's paper size, so there is only one place to set it).
- **The canvas is designed for both themes, not inherited** — sheet grid (`--color-canvas-grid`, 12% ink: 7% vanished on white), title-block fill (`--color-canvas-card`) and its **boundary** (`--color-canvas-card-border`, 50% ink → **3.53:1** on the white sheet, **5.13:1** on the dark one; two adjacent surfaces can only carry ~1.1:1 of fill contrast, so WCAG 1.4.11's 3:1 has to come from the edge). The sheet border's stored colour is now empty-means-theme-ink instead of the `#1E1E1E` sentinel, so a user who picks near-black gets near-black.
- **Crosshair guides (schematic)** — two hairlines (`--color-canvas-crosshair`, a neutral 26% ink so it never reads as selection) follow the pointer across the whole sheet, so a pin far left is visibly in line with one far right. They live in `Crosshair` (`canvas-area.tsx`) and are updated by writing `transform` straight to the two lines behind `requestAnimationFrame` — a React state update per mouse move would re-render the canvas at pointer rate. Hidden when the pointer leaves the canvas; absent in board modes, which have rulers for the same job.
- **Cross Probe works both ways and shows where it landed** — a schematic symbol finds the footprint Convert linked to it (`footprint.sourceId === symbol.id`), and a footprint walks its own `sourceId` back to the symbol; the PCB context menu gained the row it never had. On arrival the target is selected, framed, **and pulsed** (`state.probe = {id, nonce}` → the `.ix-probe` ring, two 950 ms rings, static under `prefers-reduced-motion`), then the pulse clears itself — selection alone never answered "which one?" on a dense board.
- **Rulers are board-only** — the schematic sheet prints its own zone reference (A–D / 1–4) on the frame and the status bar shows live X/Y, so the px rulers were noise there; hiding them also returns the 22px/30px gutters to the sheet (`showRulers` in `canvas-area.tsx`).
- Canvas pan/zoom/grid; selection = **mousedown is the sole authority** (click, shift/⌘-click multi-select, drag rubber-band). Delete/Esc/Ctrl+C/X/V/A/Z/Y, Hand tool (H / hold Space).
- **Left tool palette** (split-button flyouts): Wire (Wire/Bus — the bus row draws the bus trunk, not a second wire · UIUX-48) · **Power** (VCC/+5V/−5V/GND/**DGND**/Analog GND/Power GND — each places its own symbol, matching Insert ▸ Power & Ground; sits right under Wire) · **Shapes** (Rectangle/Line/Polyline/Circle/Ellipse/Arc/Bezier) · **Net Label** (Local label · **Net Flag** — the flag had no canvas home at all · UIUX-8) · No Connect · Junction · Text (Text/Note). Every option arms a real place/draft tool. **Lasso** = real freeform-polygon selection (ray-cast point-in-polygon, `state.lasso` + start/update/commit/cancel), **Area select** = real marquee (always rubber-bands on drag). **DGND** rides the GND symbol under its own name (`setToolAs("gnd","DGND")`) — the netlist names a net from the stamped text, so it really is a separate DGND net (verified in the Nets tab beside GND), the same trick VCC/+5V/−5V use on `vcc5v`. The four other label kinds (global · hierarchical · attached · Port · Off-sheet link) live in **Insert ▸ Net Label** so one canvas button doesn't hide five, and every kind stays placeable + ⌘K-searchable. *(Removed: Bus-entry, Text ▸ Field and the Eraser row — a bus is a bundle, not a conductor, so bus-entry drew nothing electrical, and Delete/Backspace · Edit ▸ Delete · right-click ▸ Delete already own deletion.)*
- **The variant list opens like a toolbar, not a pixel hunt** — a **right-click anywhere on a tool** opens its list (and never falls through to the canvas context menu), and the left-click zone that opens it is the tool's **whole bottom strip** (38×14) instead of the old 14×14 corner square; the corner triangle stays as the recognised "has variants" cue and `.ix-tool:hover` tints just that strip, so the split is visible. Escape or an outside click closes. The list itself is **portalled to `<body>` with `position: fixed` and clamped into the viewport** (flips left at the right edge, lifts at the bottom) — it used to be absolutely positioned inside the canvas frame, which sets `overflow: hidden`, so the 7-option groups were cut off in a short window (verified: 289 px list, 560 px window, fully on screen).
- Place tools (single-click) + draft tools (wire/line/polyline, click-click or press-drag).
- **Multi-sheet:** `schematicSheets` + `activeSheetId` + per-object `sheetId`; Previous/Next/Goto Page.
- New boards seed a demo RC circuit; "Load Sample Circuit".
- **Wire tool snaps** to symbol pins / wire endpoints (and grid when Snap is on) so wires land exactly on pins.
- **Net labels hug the node they name** — placing `netLabel`/`globalLabel`/`hierLabel`/`netBusLabel`/`netFlag` snaps onto the nearest pin · wire end · junction and sits **10 px above** it (under `nets.ts` `CLUSTER_TOL` = 13, so the label still joins that net — proven via the Nets tab). With a place/draft tool armed, placed objects no longer swallow the click (`toolArmed` in `placed-objects.tsx`), so a label can be dropped straight onto a wire or part — previously that click just selected the object.
- **Icons are one-per-meaning** (`icons.tsx` raw dictionary + `hicons.ts` Hugeicon overrides — Hugeicon wins when present). Controls that read differently no longer share a glyph: `find` (lines + lens) vs `zoomin` (lens + plus) · `array` (solid + ghost copies) vs `grid` · `dAnnotate` (part + numbered badge) vs `pText` · `pBus` (trunk + branches) vs `pWire` · `pPolyline` (segments + vertices) · `dRule` (rule checklist, not a ruler) · **`dDrc`** (two coppers with the clearance gap measured between them — board rules are about spacing, so it no longer reads as a second tick beside `dCheck`) · **`tLenTune`** (one meandering net) vs **`tDiffLenTune`** (two rails, one meandering — pair skew, not single length) · `pDiffFlag` / `pKeepout` / `pPartMask`. The **supply family** (`pwrVcc · pwr5v · pwrN5v · pwrGnd · **pwrDgnd** · pwrAgnd · pwrPgnd`) draws the real schematic symbol each row places (DGND = the ground stack with a D mark, so it can't be read as plain GND in a list holding both), and the **label family** (`pNetLabel · pGlobalLabel · pHierLabel · pAttachedLabel · pPort · pOffPage`) draws each kind's own outline — tag · stadium · hexagon · tag-on-wire · port · sheet-edge arrow. Where the closest Hugeicon collided with another control, the key is left out of `hicons.ts` on purpose so the hand-drawn glyph wins (noted there). **A menu row's glyph is drawn for that row, including the parents**: `align` is a guide with two objects flush to it (both Arrange menus — it was `AlignSelectionIcon`, a bare frame, while its own six children read clearly · UIUX-38/59) · **`group` vs `ungroup`** — one boundary whole around two shapes, then broken with the shapes adrift (they shared `GroupItemsIcon`, so the two opposite commands were one picture · UIUX-40) · **`tRouteCorner`** (a mitred bend with the rounded alternative ghosted over it) vs **`dFillet`**, which used to borrow the same `pArc` (UIUX-56/61) · **`tRouteWidth`** (three weights of one line) vs **`tGloss`** (a smoothed track + polish mark), which both used to be the chain-link `wire` (UIUX-60) · **`dChamfer`** vs **`dFillet`** — the same square, one corner cut straight and one rounded, with the corner itself the emphasised stroke so the two differ at 24px (UIUX-61).

## Schematic connectivity, ERC, netlist & annotation (`nets.ts`)
- **Live netlist** — symbol kinds carry pin anchors (`SCHEM_PINS`); `computeNets()` union-finds pins + wire endpoints into nets, named from net-label / power / port symbols (same name merges) else auto `N1…`. Pure/derived — always reflects the drawing.
- **Auto-junction** — a wire ending on another wire's **interior (a T)** is electrically joined (on-segment union) and a **junction dot** is auto-dropped there on wire-finish.
- **Buses are bundles, not conductors** — a bus carries a `PREFIX[lo:hi]` name and **expands to member nets**: `computeNets` excludes buses from the electrical graph, so branch wires connect by member label (`BUS_D3` here = `BUS_D3` there, via same-name merge) and each member is its own net in the netlist. Bus membership (for ERC) is geometric (a pin/branch endpoint on the bus line).
- **Nets tab** (navigator) lists the live nets with object counts; clicking highlights the net (members via connectivity → `highlightedMembers`, since schematic objects have no stored `net`).
- **ERC** (`runErc` + `ERC_RULES` catalog) — a real rule engine over the live connectivity, emitting findings on the EasyEDA-Pro **5-level severity scale** (Note · Warning · Error · **Fatal**). Enforced rules: floating pins, free/dangling wire, single-connection net, label-not-connected, duplicate & unannotated & mis-formatted designators, empty Value, netflag/netport-needs-name, illegal net name (charset/length), illegal bus name, multiple-net-names-on-one-net, global-net short, port/flag/off-page name-vs-wire mismatch, unpaired differential pair, overlapping-unconnected pins (bare pin tips with no wire/junction join), **bus rules** (illegal bus name, bus-branch member naming `PREFIX[lo:hi]`, and netport/netflag/off-page ↔ bus name-match — a bus bundle legitimately carries many member names, so multiple-net-names is suppressed on it), and the **pin-conflict matrix** (Connection tab). Severities live in one catalog (`ERC_RULES`). The pin-conflict rule reads each pin's electrical type (`SCHEM_PIN_TYPES` / `POWER_PIN_TYPE` / `props.pinType`) and looks up the pair in `defaultPinMatrix()` — so two op-amp outputs = Error, Power↔Ground/OUT↔Power = Fatal, while normal passive nets stay clean (matrix default is Ignore; a No-Connect flag suppresses the net). Results show in the bottom **DRC/ERC tab** (Fatal/Errors/Warnings/Notes counts) via "Electrical Rule Check" / Design ▸ Run design check, **and on the canvas** (UIUX-81, `drc-markers.tsx`): each finding names the objects it is about (`ErcIssue.ids`, filled by `emit`), so the offending wire · pin · part · flag is **ringed where it sits** — a dashed circle sized to that element's real bounds and coloured by severity (Fatal · Error · Warning · Note), with the severity dot and its tooltip on the ring. A finding that names nothing keeps the small positional marker, and the bottom tab's **Show on canvas** turns the layer off. Verified against a sheet built to trip one rule per severity: overlapping pins (Fatal), an unnamed Netflag (Error), GND shorted to VCC (Warning) and an unannotated `R?` (Note) — 8 dashed rings, four distinct severity colours, and the shorted wire's ring 232 px wide against a symbol's 32. **Config-driven** — `runErc(objects, cfg)` reads the **Design Rules dialog** config (`state.designRules`, persisted per-project in the doc): a disabled rule is skipped, a re-severitied rule reports at the tuned level, and the pin-conflict matrix + its master toggle come from the config. The dialog (Save → `setDesignRules`) is the real tuning surface, not a stub. **Its shell is IDEEZA's own** (UIUX-39, titled **Electrical rules** — the term the Design menu and the toolbar's ERC control already use; “Design Rules” pointed at the board's dialog): a category rail (Nets & connectivity · Components · **Agile Modules** · Pin conflicts) with per-category *on / total · checked* counts, a whole-config summary (`23 of 35 rules on` + severity chips), a rule filter, an **Only rules the engine checks** toggle and Enable/Disable-shown. **A rule row is one decision, not two controls** — it used to carry EasyEDA's anatomy (a checkbox, a `01`/`02` number, the rule text, a severity badge on the right), where "on" and "how loudly" were separate switches that could contradict each other. The number and the checkbox are gone; the row is the rule text over a state line in words (*Reported as a warning* · *Not reported* · *Not checked yet*) with one **five-stop report level** on the right — **Off · Note · Warn · Error · Fatal** — so the current level and every alternative are visible at once instead of hidden behind a dropdown. `Off` writes `enabled:false` and a level writes `enabled:true` + that severity, so the engine's model is untouched (a stored `Ignore` severity reads as Off rather than leaving the control blank). Rules the engine doesn't implement yet carry a **“not checked yet”** badge (from `ERC_ENFORCED_ROWS`/`ERC_RULE_AT`, exported from `nets.ts` as the inverse of `ERC_TO_DIALOG`) so a toggle never pretends to matter. **The config contract is load-bearing** — `runErc` looks rules up by category + row index, so the dialog never reorders or filters the stored arrays; the search box filters only what is displayed and every row keeps its true index. **Every toggle is keyboard-operable** — the rule rows, the *Only rules the engine checks* filter and the pin-conflict master were `<span onClick>` around a painted box, so Tab never reached the controls that decide what the checker reports; they are `<button role="checkbox" aria-checked>` now (`CheckRow`), and the design-system `Checkbox` gained a `decorative` flag so the painted box inside a labelled control no longer announces a second, nested checkbox role (verified: 0 nested roles). **The footer carries the decision alone** — Cancel (discards the buffer) · **Save & check now** (saves, then really runs `runErcCheck` and opens the results tab — the old “Verify Now” only switched tabs) · Save. The set-level actions (**Import a rule set… · Export this rule set · Restore IDEEZA defaults**) moved to the foot of the category rail under a *Whole rule set* label (`RailAction` in `modal-kit.tsx`), beside the set they act on, instead of sitting in one five-button row where the destructive one is a neighbour of Save. *Bus rules validate names against `PREFIX[lo:hi]` and the netlist expands each member as its own net. Feature-blocked (not enforced): reuse-block rules (Net-reuse #1-3), unconnected-wire-name-visibility (#18), supplier-part match; library-guaranteed component rules are intentionally excluded.*
- **Netlist export** (`buildNetlist` + `exportNetlist`) — Project ▸ Export ▸ Netlist downloads a real `.net` (nets → component pins), computed across **all sheets** with global nets (power / global label / port) merged and local nets sheet-qualified.
- **Export Sheet dialog** (UIUX-67 + UIUX-65, `SheetExportModal` + `captureSchematicSvg(opts)` + `buildSheetPdf`) — the schematic's Export ▸ PDF used to open the *board's* Export Document dialog (an EasyEDA transcription that exported the PCB model, so the file never held the sheet); the schematic Export menu now carries one **Sheet (PDF · PNG · SVG)…** row (the one-click PNG/SVG rows and `exportSheetImage` went with it — one home). **Two panes: calibration left, live preview right** — the preview `<img>` renders the very capture the export writes (re-captured after paint on every frame/ink/range change, with real px dimensions captioned), so it cannot disagree with the file. IDEEZA's own vocabulary: **Format** · **Range** (*This sheet* · *Selection (N)* — the editor's selection is the region tool, exported as a content crop with the frame checkbox muted + reasons when empty — · *All sheets (N)*) · **Ink** (*As drawn* / *Black on white (print)* — the capture maps every colour by its distance from the page tone, so both themes print the same black-on-white sheet) · **Detail** (1–3× raster scale, muted for SVG) · **Sheet frame** checkbox · file name (defaults to the sheet's slug, or the project's for All sheets; hand edits stick) · a live summary; footer Cancel · **Print** (PDF blob in a new tab, range-aware) · Export, disabled when the chosen range is empty. **All sheets is a real walk** — snapshot the active sheet + selection, `gotoSheet` each sheet, wait for the canvas to render, capture, then restore both; PDF = one file with a page per sheet (`buildSheetPdf(pages[])`, multi-page DCTDecode with byte-accurate xref), PNG/SVG = one sheet-slug-suffixed file each, empty sheets skipped and said so. `captureSchematicSvg` gained `onlyIds` (selection crop). **The frame & title block export for real** — the capture serializes the live `data-sheet-frame` DOM (backgrounds/borders → rects/lines, leaf text → `<text>`, the logo `<svg>` cloned like a glyph), same no-second-copy philosophy as the object capture. Also fixed here: **wires had vanished from every sheet export** since the pick-band rework (the id sits on the transparent 9px band, and the capture cloned only the id node) — an invisible id-carrier now defers to its visible twin. Board's Export ▸ PDF (`DocumentModal`) is untouched. Verified: 35 + 14 CDP checks — bytes of all formats, frame on/off, print ink, preview reactivity, selection crop, 2-page PDF + per-sheet PNGs with sheet restore, both themes.
- **Parts number themselves as they land** (UIUX-3, `nextDesignator` in `types.ts`) — `placeObject` and the part picker stamp the next free designator per prefix over the whole schematic (R1 · R2 · C1 …), so a sheet no longer fills with `R?` waiting for a manual pass; an explicit `placeText` (a named supply rail) still wins, and the picker keeps the part number in `props.mpn` — which is where the BOM's MPN column reads it, and it used to sit in `text`, so the BOM's Designator column printed part numbers. `ANNOT_PREFIX` is shared with the Annotate dialog, so placement and re-numbering can't disagree. With numbering automatic, **Annotate Designator left the Design menu and the toolbar**; re-numbering a whole sheet keeps its home on a component's right-click menu.
- **Annotate / Reannotate Designators** — real auto-numbering by kind in reading order, **each prefix counting independently from the start number** (R1,R2 · C1,C2 — the old loop shared one counter, so a lone capacitor came out C2). `ANNOT_PREFIX` covers `resistorBox`/`transistor`/`opamp` too (they were silently skipped). The dialog is a **live dry run**: the same plan the button commits is previewed as a count plus sample `C? → C1` lines, and no-op assignments are excluded, so “nothing to change” means exactly that. Shell is IDEEZA's own — segmented Assign/Clear, Which-parts select, direction tiles, start-number stepper.

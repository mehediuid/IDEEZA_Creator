# Features — the Earn layer

Part of the feature inventory ([index](README.md)). Keep it current: [AGENTS.md › Keeping docs current](../../../AGENTS.md#keeping-docs-current-required). Specs: `docs/superpowers/specs/2026-10-11-build-earn-p0-design.md` (Build and Earn P0) and `…-p1-design.md` (P1). The project page (`/projects/[id]`) is engineering; everything that makes money from a project lives here.

## Earn area (`/projects/[id]/earn[/<tab>]`)
- **Routes** (`app/(create)/projects/[id]/earn/`): one `layout.tsx` (`components/projects/earn/earn-shell.tsx`) reads every store once through the project page's `useProjectPageData`, with the same viewer and `view.canCtx`; `page.tsx` is the Overview and `[section]/page.tsx` the other tabs (`sell` · `plan` · `money`). Moving between tabs keeps the header, the tabs and the read, and swaps only the tab body (`earn-context.tsx`). Every path comes from `lib/manual/earn-route.ts`: a part of a tab is the tab's path with its id as the hash (`earnHref(id, "customers", { sale })` → `/earn/money?sale=…#customers`), scrolled to once the tab renders. The old section addresses redirect on the server (`earnSectionRedirectOf`): `editions` → `sell#copies`, `splits` / `customers` / `rights` → `money#…`, a customers `sale=` kept. An unknown section answers 404, `/earn/overview` goes to `/earn`, and the old `/projects/[id]/business-plan` redirects to `/earn/plan`.
- **Layout** (`surface.tsx`): one left-aligned column at most 760 px wide holding the header, the tabs and the tab; one card style (`EARN_CARD`), one heading scale (an h2 per section with one plain sentence under it, an h3 inside), 32 px between sections; empty states are one line and one action, left-aligned. At most one violet control per tab.
- **Header** (`earn-header.tsx`): "← {project}" back to the project page, the h1 "Earn" and one status pill in words from the commercial axis (`earnStatusOf`: *Not for sale yet* · *Minted* · *On the marketplace* · *Listing paused* · *Part sold* · *Sold out* · *Given away*), the lock line once sold in full, and, once minted, **Preview as others see it**, a ghost link to `/projects/<id>?view=buyer`. Nothing in the header or the tabs prints.
- **Tabs** (`earn-nav.tsx`): Overview · Sell · Business plan · Money, page links with `aria-current="page"` drawn with the project page's tab-strip classes (`tab-strip.tsx`); one row that scrolls sideways at phone width (the edge it can scroll past fades, the current tab is brought into view), 44 px on a phone or a coarse pointer, never violet.
- **Owner only** (`canOpenEarn`): a preview (`?view=buyer`, `?view=contributor&as=`) keeps its banner and gets "Only the owner can manage earning" with a link back to the project page carrying the preview.
- **Focus**: arriving focuses the h1; a tab change keeps focus on the link and says the tab in the page's polite live region; the document title is "{tab} · Earn · {project} · IDEEZA".

## Tabs
- **Overview** (`overview.tsx`): the path ① Mint → ② Sell → ③ Get paid (`earnPathOf`), done steps ticked and the current one saying *You are here*, then one card for the current step (`earnNextOf`): its title and one sentence on why; while its commit point has steps missing, **Before you can mint** / **sell** lists only those, each with its one-tap fix (`LevelCheck` over `commitCheck`, the steps the project page's Earn button counts), and the step's own action (**Start mint**, **Choose what to sell** → the Sell tab), the tab's one violet control, shows only once none is missing. Once something is live (listed, paused, given, sold, or copies on sale without the Main NFT) the card says the state in plain words, a facts row (`earnLiveFactsOf`: price, copies sold of the copies made, whole project and products, *Bought by* (how many people, *Nobody yet* at none), and earned, the sales' payouts summed per token) and a link to where it's managed. Once verified, "Identity verified (demo)" with **Reset**.
- **Sell** (`sell.tsx`, `editions.tsx`; the owner's selling rules 2026-10-11): **What you can sell**, three rule cards (Main NFT: the project itself, whole project only; Physical NFT and Virtual NFT: whole project or one product) under *each one is listed on its own*; **Whole project · {name}**, three rows (Main · Physical · Virtual), each its state in words and one quiet button: the Main row's **Sell** is the mint flow before a mint, else `ListingFlow` (below L3 *Before you can list* stands under the row), and **Manage** opens the listing's own controls (`ListingBody`: Edit · Remove · Relist · Bidding history · Close auction); then the note that selling the Main NFT sells the project, and **Mint details**; **One product at a time** (`#copies`), a Physical and a Virtual row per product. A copy row (`copyRowStateOf`) never asks the Main listing: **Sell** opens the copies flow with the kind preset (not minted: the mint flow; Given, sold in full, an unknown collection or a dropped product grey it with the reason), and **Manage** opens that scope's tracks (`EditionTracks`: Personal use, Price, Price with future updates, Copies sold; Edit · Remove listing · Add copies) with *Sell … copies too* while the other use is open. Whole-project copies are tracks with `productId` = `PROJECT_SCOPE`.
- **Sell copies** (`sell/sell-flow-dialog.tsx`, `sell-steps.tsx`, `lib/market/sell-flow.ts`): "Sell {virtual|physical} copies of {the whole project|product}", the kind preset by the row, two steps with a "Step n of 2" track. **Copies and price**: Copies (only for a new track), Token, Price with *You get {price − 2.5 % fee} per copy*; a built product adds the required "How you'll make and ship it" note (≤ 1,000 characters) and three promises (lead time, refund, "I'm the seller"); **More options** (closed) holds Price with future updates (empty = the price), Use (Personal / Business, the first open one) and Royalties (default 10, *a share of resales, if marketplaces honour it*). `effectiveTermsOf` fills the empty ones for both the checks and the stored listing. **Review**: what, copies, price, network; the rules (the product's AI video, or every product's for the whole project, with Generate AI video on top; ownership; the make-and-ship note back on step 1; never the Main listing); the ladder check (L3 virtual, L4 physical); the ownership box while unconfirmed, the lazy-mint box and *nothing here promises you income*; then **Sign and sell**, the dialog's one violet control, which makes Create *n* lazy NFTs (`createEditions`, when new) then Sign the listing (`listEdition`); a listing left unsigned keeps the copies created and the flow picks up at the listing. Next checks only its step and focuses the field at fault; Back keeps everything; closing with anything entered asks first. The note and promises are stored per scope in `ideeza:project:edition-terms:<id>` (swept on delete).
- **Business plan** (`plan.tsx` over `business-plan/plan-page.tsx`'s `BusinessPlanPanel`): with no plan, "Business plan" and one line with **Generate business plan** (the Generate and Writing dialogs); a progress row while it writes (Show progress · Stop writing) or after it stopped (Continue writing), then the plan under its h2 with versions, Edit, Regenerate, Print or save as PDF and Delete (which lands back on the empty state); each plan section is an h3.
- **Money** (`money.tsx`), three sections: **Splits** (`#splits`): the ownership line (`ownershipRow`) over the roster with each share, the over-100 % warning, Add contributor and its add/edit dialog, removal, and Preview, which opens the project page as that contributor; empty, *No contributors yet.* and Add contributor. **Sales** (`#customers`, Testnet demo): once the project has a sale, **Payouts** (`ladder/request-payout.tsx`): what its sales paid you and what isn't requested yet, per token, and **Request payout (demo)** (L4; below it, *Before you can request a payout* in its place), which stores one request in `ideeza:commerce:payouts` and sends nothing, with the last request under it; then the project's Sales panel; `?sale=<id>` opens and focuses that sale; empty, *No sales yet.* and, before a listing, Go to Sell. **Rights** (`#rights`): the legal details (patent, copyright, trademark, inline edit; **Add legal details** when there are none) and, for a project given under a license, the license.
- **The gating ladder** (`lib/commerce/ladder.ts`, spec P1-4): `earnLevelOf(facts)` → `{ level 0–4, next }`, cumulative: L1 Drafts needs something built (every project has a product), L2 Mint the demo wallet connected, ownership confirmed and every product's video ready, L3 Sell & editions minted (the commercial axis, `commercialStateOf`), a license chosen and the payout wallet (every mint has one), L4 Physical editions & payouts the demo identity check. Engineering is never gated. The project page's Earn button counts the next commit point's steps (`commitStepsOf`). Every commerce commit point asks `useCommitCheck(point, …)` and shows the missing steps inline under *Before you can {commit}* (`LevelCheck`), the commit aria-disabled (or, on the Overview and Your project, left out) until they're done; a step the call site gates itself (its readiness gate, its ownership box) is left to it: the mint flow's **Sign** (L2 for Keep private and Give, L3 for a Sell, which lists as it mints; its Details asks the license), Add to marketplace / List another share and **Relist** (L3), the edition flow's **Sign** (L3 Virtual, L4 Physical) and **Request payout** (L4). The fixes: Connect wallet (the Demo wallet dialog), Confirm ownership (writes `ownerConfirmedAt`), Make videos in Media, Go to mint and Set payout wallet (Earn › Sell), **Choose a license** (the Brief's list; writes the draft's license) and **Verify identity**.
- **Verify identity (demo)** (`ladder/verify-identity-dialog.tsx`, `lib/commerce/kyc.ts`): a name and a country, both required and neither stored (autofill off), under "Demo — no real verification"; it stores only `ideeza:commerce:kyc` = `{ status: "verified", at, demo: true }`. Asked only by physical editions and Request payout; Reset removes it.
- **Selling a share** (`lib/commerce/share-copy.ts`): wherever a share of the project is sold (the listing fields in the mint flow and the listing dialog, the mint flow's review, the buyer's rail, the purchase and bid requests) the copy promises no return and carries the fixed note "Demo on a testnet. Selling a share of a project can be regulated as an investment where you live; this is not available for real money."; royalties read "*n*% · a share of resales, if marketplaces honour it".
- **Sold in full**: every section reads only, through the moved components' own `can(viewer, …, view.canCtx)` and lock: no listing start, the edition cards' sold-in-full note (no rows), the plan's Edit, Regenerate and Delete disabled, no Add contributor, no Edit legal details.

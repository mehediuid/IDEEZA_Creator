# Messages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People talk to people in `/messages`, on the demo identities, with five entry points, Requests and safety, as specified in `docs/superpowers/specs/2026-10-13-messages-design.md`.

**Architecture:** A pure model in `src/lib/messages/` (rules over one `MessagesData` value, node:test) under a local store (`ideeza:messages` through `key-store`, files in IndexedDB) and a small action layer; the UI reads `useMessages()` + `useMessagePeople()` + `useActingAs()` and calls the actions. A server adapter later replaces `store.ts` + `actions.ts` only.

**Tech Stack:** Next 16.2.9 App Router (read `node_modules/next/dist/docs/` before route code), React 19, TypeScript, Tailwind preset over `src/styles/tokens.css`, design-system atoms in `src/components/ideeza/`, icons `@hugeicons/core-free-icons` through `components/dashboard/icon`.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-10-13-messages-design.md` — every rule, string and layout there is binding.
- Rules: `AGENTS.md` (tokens only, light + dark, no `style={{}}` except data, line height pairs with size, no card in a card, one control one home, portalled menus, 44 px targets at phone width, no em-dash doing a full stop's job).
- Type scale: all new text ≥ 14 px (`text-md` + `leading-md`); `text-sm` is 12 px here and only for a micro-label. `cn` (twMerge) doesn't know `text-md`: don't override an atom's `text-sm` with it, render your own element. Spacing scale is the project's own (`size-8` = 16 px): use exact `size-[32px]` for controls.
- Opacity modifiers don't work on token colours (`bg-bg-page/60` compiles to nothing): use `color-mix(…)` or a token.
- A bordered `<button>` names `border-solid`.
- No new dependencies. No `console.log`. Comments only where the logic isn't obvious, matching the files around them.
- Never `git add -A`; never touch files outside your task.
